# 模板三抽图模型重构计划（规则块模型）

> 状态：**待批准实施**（计划成稿，代码未动）。
> 依据：`docs/ng-regens-v4-抽图模型.md`（模型来源文档）+ `src-tauri/assets/base_config.json`（Version 4，43008 字节 → 改名为 `assets/standard3.json`）。
> 分支：`tauri-v2`。本文档自包含，可在无对话上下文的情况下直接接手实施。

## 0. 一句话目标

模板三的抽图模型换成「规则块 + 四种规则形态 + default 语义」，同时把每个头像包模板标准拆成**一个自包含模块**（schema + 抽图规则 + 单测同文件），并把文件命名统一到「标准号 N」这一条主轴上。

## 3. 模型数据实测基线（实施后必须逐项复现，可直接当断言用）

对 v4 规则表全量解析 233 国 × 11 码 = **2563** 组合：

- **100% 可解析**；所有被引用的目标目录都在 62 清单内；62 个目录全部至少被一条规则指到（无死目录）。
- 规则形态：`default` 1833 / `directly` 591 / `random` 128 / `weighted` 11（合计 2563）。
- 选块层级：`_DEFAULT_` 1694 / 族群块 451 / 国家块 418。
- 4 个族群块（Afrocaribbean 27 国 / CaucasianNA 2 / Mestizo 16 / SouthConeSA 3，共 48 国）；其中 7 国（COL CUB DOM ECU GUA PAN VEN）另有国家块 → 优先级①真实生效，不是理论。
- **权重和只有 99 与 100 两种**（例：`DOM/1 = {ethnicities:[Mestizo,NorthernSA], weights:[66,33]}`）→ 必须按 Σ 归一，禁止假设 100。
- `_DEFAULT_` 块不变量：c9 恒 `directly → MixedRace`，其余 10 个码全 `"default"`。这是全表唯一的跨国家硬编码。
- 与模板二的 14 目录清单**零重合** → `classify` 现在唯一的重合名（`Scandinavian`）随之消失。
- `DefaultCodes`：233 键，与 `Ethnics` 键集完全一致。

## 4. 目标模块结构（D4）

```
src-tauri/src/templates/
  mod.rs          PickRule trait、PickedImage、for_layout 分发、IMPLEMENTED_TEMPLATES、
                  RuleConfig 聚合（builtin / load / ensure_user_files / folder_lists / rule_files）、
                  validate_registry()（§4.2 守卫）、两个无标准语义的机械工具
                  （filter_pools / pick_from_pools_flat）
  standard1.rs    标准一   Standard1Rule                     —— 无 json、无 Config 类型
  standard2.rs    标准二   Standard2Config + CodeRule + apply_code_rule + Standard2Rule
  standard3.rs    标准三   Standard3Config + MappingRule + validate() + Standard3Rule + Fallback
  unknown.rs      非标准   UnknownRule                       —— 空包 / 无法识别的退化布局
```

### 4.1 命名主轴：标准号 N 是唯一身份

| 位置 | 规则 | 标准一 | 标准二 | 标准三 |
|---|---|---|---|---|
| 模块文件 | `templates/standardN.rs` | `standard1.rs` | `standard2.rs` | `standard3.rs` |
| 配置类型 | `StandardNConfig` | **无**（无可配数据） | `Standard2Config` | `Standard3Config` |
| 模型类型 | `StandardNRule` | `Standard1Rule` | `Standard2Rule` | `Standard3Rule` |
| `RuleConfig` 字段 | `standardN` | **无** | `standard2` | `standard3` |
| 内置默认 | `assets/standardN.json` | **无** | `standard2.json` | `standard3.json` |
| 用户可编辑 | `data/rules/standardN.json` | **无** | `standard2.json` | `standard3.json` |
| 命令 name 参数 | `"standardN"` | 不暴露 | `"standard2"` | `"standard3"` |

- **标准一没有 json 是合理的，不是遗漏**：它的定义就是"无子目录 + 根目录有图"，抽图是纯随机，没有任何可配数据 → `RuleConfig` 里没有它的字段，`folder_lists()` 里也没有它（`classify` 靠 `subdirs.is_empty()` 判它）。它也不在 `IMPLEMENTED_TEMPLATES` 里 —— 那个拦截只看 `PackLayout::Standard{template}` 分支，标准一/空包/Unknown 根本不经过它。
- **空包与 Unknown 不是标准**：它们是退化布局，共用 `unknown.rs`；对外的标准号映射（`Empty → 1`、`Unknown → 0`）只此 `PackLayout::standard()` 一处。给它们编 `standard0.rs` 会让"标准号"这个概念失去唯一含义。
- 用户新增标准四时**不引入主题名**：文件名/类型名只按号排（`standard4.json` / `standard4.rs` / `Standard4Config` / `Standard4Rule` / `"standard4"`），"这个标准叫什么"只写在 README 与 json 的规则数据里。

### 4.2 以后加标准四/五/六/七：六步配方

判定层零改动（`classify` 完全数据驱动），新增一个标准只碰这六处：

1. `assets/standardN.json`：`FolderList` + 该标准自己的规则字段（各标准 schema 互不约束，不要求同构）。
2. `templates/standardN.rs`：`StandardNConfig`（含 `validate()`）+ `StandardNRule: PickRule` + 本文件自己的单测。**只允许 import `templates::mod` 的 trait 与两个机械工具**。
3. `assets.rs`：`STANDARD{N}_RAW = include_str!("../assets/standardN.json")`；`lib.rs` 无需改（`mod templates` 已声明）。
4. `templates/mod.rs` 登记：`RuleConfig` 加字段 → `builtin()`/`load()`/`ensure_user_files()` 各加一份 → `folder_lists()` 加一行 `(N, &cfg.standardN.folder_list)` → `for_layout()` 加一个 `match` 分支 → `rule_files()` 加一项 → `IMPLEMENTED_TEMPLATES` 加 `N`。
5. `commands.rs`：**零改动**（P1 已把 `save_rule_file`/`rule_file_path` 改成查 `templates::rule_files()` 单表；现状是每个标准各 `match` 一次，模板一多就要改多处、还容易漏挂校验）。
6. 前端：`api.ts` 的 `RuleName` 联合类型 + `RuleEditor.svelte` 的 `NAMES/LABELS` + `text.ts` 标签 + `layout_label(N)` 文案，各加一项。

**登记冲突守卫**（给"四五六七个标准"准备的，不做的话标准一多必踩）：`validate_registry()` 在 `RuleConfig::load` 里检查任意两个标准的 `FolderList` 不构成包含关系（A ⊆ B 或 B ⊆ A）。理由是 `classify` 的超集轮与子集轮都是"按 `folder_lists()` 的登记顺序先命中先赢"，`facepack.rs:57` 注释里那句「超集间互斥——各模板清单互不包含」目前只是**恰好成立**；一旦被破坏，就会出现"62 目录的包被判成标准三、其实该是标准五"这种静默错判。报错指名两个标准号与重合的目录名。真正交叉（既非超集也非子集）仍判 Unknown；子集轮的重合歧义按登记顺序定夺 —— 登记顺序本身就是唯一真源，不引入"清单大的优先"这类第二套规则。

### 4.3 模块纪律（本次重构的验收标准）

1. `standard2.rs` 与 `standard3.rs` **互不 import**；任何标准文件不 `use` 另一个标准的类型。
2. `mod.rs` 只允许存在「跨标准无语义」的东西：trait、分发、配置聚合、`filter_pools`、`pick_from_pools_flat`。选目录与选图的**业务决策**一律在各自标准文件内。
3. `PickRule::pick` **去掉 `config` 形参**（现状 4 个实现里 3 个不用它）。每套规则构造时只拿自己那份配置，`RuleConfig` 只在 `for_layout` 出现一次。这是消除耦合的主要一刀。
4. 单一真源不变且只有一处：判定 `facepack::classify`，分发 `templates::for_layout`，标准号映射 `PackLayout::standard()`，登记 `RuleConfig::folder_lists()`。
5. 代码与 UI 文案不写世系（D1）：注释只描述当前模型做什么，不写"原来是什么、从哪个版本升级来"。

## 5. 标准三类型与签名（`templates/standard3.rs`）

```rust
/// 标准三规则配置：族群映射规则块。PascalCase json。
#[derive(Debug, Clone, Default, Serialize, Deserialize)]
#[serde(rename_all = "PascalCase")]
pub struct Standard3Config {
    #[serde(default)] pub folder_list: Vec<String>,                     // FolderList（62 个图像池）
    #[serde(default)] pub ethnics: BTreeMap<String, String>,            // Ethnics：国籍 → 本国基础池
    #[serde(default)] pub default_codes: BTreeMap<String, Vec<u8>>,     // DefaultCodes：透传，不参与抽图（§8）
    #[serde(default)] pub ethnicity_mapping_rules:
        BTreeMap<String, BTreeMap<String, MappingRule>>,                // EthnicityMappingRules：块键 → 码 → 规则
    #[serde(default)] pub version: u8,                                  // Version，必须为 4（§7.1）
    #[serde(default)] pub fallback: Fallback,                           // Fallback：目标目录不可用时的第二级（D3）
}

/// 规则块里的四种形态（与编辑器文案一一对应；json 无此键/类型不符都要报错，不许静默降级）。
#[derive(Debug, Clone, PartialEq)]
pub enum MappingRule {
    Default,                                            // "default"
    Directly(String),                                   // {"typeOfMapping":"directly","directory":"X"}
    Random(Vec<String>),                                // {"typeOfMapping":"random","directory":["A","B"]}
    Weighted { dirs: Vec<String>, weights: Vec<f64> },  // {"typeOfMapping":"randomWithWeight","directory":{"ethnicities":[…],"weights":[…]}}
}
// 手写 Serialize + Deserialize（不用 serde untagged）：untagged 失败时只报
// "data did not match any variant"，而这份 json 就是用户在规则编辑对话框里直接改的对象，
// 错误信息必须指名道姓（哪个块键、哪个码、实际看到的 typeOfMapping）。
// weights 用 f64 + Σ 归一：整数百分比（60）与小数（0.6）两种写法都能读，不需要分支。

#[derive(Debug, Clone, PartialEq)]
pub enum Candidates { Single(String), Uniform(Vec<String>), Weighted { dirs: Vec<String>, weights: Vec<f64> } }

/// 一次 (国籍, 种族码) 的解析结果。
pub struct Resolution { pub candidates: Candidates, pub owner_folder: Option<String> }

impl Standard3Config {
    /// 结构校验（§7）。RuleConfig::load 与 save_rule_file 共用的唯一入口。
    pub fn validate(&self) -> Result<(), String>;
    /// 解析 (nat, code) → 候选目录 + 本国基础池。None = nat 不在 Ethnics（交第二级兜底）。
    pub fn resolve(&self, nat: &str, code: &str) -> Option<Resolution>;
    /// 纯函数：按权重取候选下标（r ∈ [0,1)），Σ 归一在函数内做，供单测直接喂 r 断言分界。
    fn weighted_index(weights: &[f64], r: f64) -> usize;
}

/// 标准三抽图规则：规则块模型。
pub struct Standard3Rule {
    pools: BTreeMap<String, BTreeSet<String>>,           // FolderList 过滤后的一级目录池
    recursive_pools: BTreeMap<String, BTreeSet<String>>, // Fallback::Random 用的递归全池
    cfg: Standard3Config,                                // 构造时只拿自己这份，之后不再看 RuleConfig
}
impl Standard3Rule {
    pub fn new(faces_map: &BTreeMap<String, BTreeSet<String>>,
               recursive_pools: &BTreeMap<String, BTreeSet<String>>,
               cfg: &Standard3Config) -> Self;
}
impl PickRule for Standard3Rule { /* exclude_used 沿用 record_from 全路径口径；pick 见 §6 */ }
```

`for_layout` 分支：`PackLayout::Standard { template: 3, .. } => Box::new(Standard3Rule::new(&scan.faces_map, &scan.recursive_pools, &cfg.standard3))`，其中 `RuleConfig { standard2: Standard2Config, standard3: Standard3Config }`。

## 6. 抽图算法（唯一实现处，约 60 行）

```
输入：player.primary_nat = N，player.ethnicity_code = c（"0".."10"）
     不使用第二国籍（sec_nat 不参与本模型；模板二的码修正只活在 standard2.rs）。

1) 选块（纯查表，不硬编码族群名）：
   ① rules[N]                N 是三字码，作为块键存在 → 国家级块
   ② rules[Ethnics[N]]       Ethnics[N] 是目录名，永不与三字码相撞 → 查表即命中族群块；
                             查不到自然落到 ③（不需要「仅当属于某族群」这条额外判断，等价）
   ③ rules["_DEFAULT_"]
2) rule = 块[c]；owner_folder = Ethnics[N]（Some/None）
   【关键简化】"default" 的三种归属者语义（国家块 / 族群块 / _DEFAULT_）在此选块顺序下
   恒等于 owner_folder = Ethnics[N] → 只有一处实现，不是三个分支。
3) rule → Candidates：
   Directly(d)   → Single(d)
   Random(list)  → Uniform(list)       等概率
   Weighted(d,w) → Weighted            按 Σw 归一（Σw 可为 99）
   Default       → Single(owner_folder)；owner_folder 为 None → 直接第 6 步
4) 过滤候选：只留 pools[dir] 存在且非空的目录
5) 抽目录 → 抽图：Single 直取；Uniform 等概率；Weighted 走 weighted_index
   池内随机取词干；!duplicates 时把选中的图从池中移除
6) 第一级回退：候选全不可用 → 用 owner_folder（在池内且非空即取）
7) 第二级回退：仍不可用（含 N ∉ Ethnics）→ 按 cfg.fallback：
   Random → pick_from_pools_flat(recursive_pools)
   Skip   → None（该球员不生成映射）
```

## 7. 结构校验（`Standard3Config::validate`，§3 不变量的守卫）

按顺序检查，报错信息带具体键名（`save_rule_file` 直接回显给用户）：

1. `version != 4` → `仅支持 Version 4 的规则文件（当前 Version {v}）`。这条同时挡住了空文件、被删键的文件、以及非本格式的旧规则文件（缺 `Version` → 取 0）。
2. 块键合法域：`EthnicityMappingRules` 的每个键 ∈ `Ethnics` 键集（国家级块）∪ `FolderList`（群组块）∪ `{"_DEFAULT_"}`。→ 上游其他格式的专有键（如 `_country_specific_default_`）会在这里被报「未知规则块键」，**不做兼容**。
3. 每个块的码集合恰为 `{"0".."10"}` 全枚举，无缺口、无多余键。
4. 所有规则引用的目录 ∈ `FolderList`；`Ethnics` 的值 ∈ `FolderList`。
5. `Weighted`：`dirs.len() == weights.len()`、全部 `> 0`、Σ > 0。
6. `FolderList` 去重后非空；`DefaultCodes` 键集 ⊆ `Ethnics` 键集（透传字段只做轻量检查，不要求相等，避免用户精简表时被卡住）。

延续现有原则（`rule_config.rs` 文件头注释）：用户文件**格式错误 → 报错中止、不静默回退内置默认**，错误信息含文件路径。

## 8. `DefaultCodes` 与 `Version` 的处置

- `DefaultCodes` 保留在 schema 中，**透传但不参与抽图**：抽图用的种族码来自 RTF 的 `ethnicity_code`。`save_rule_file` 会原样写回，用户从上游拷整份配置不丢数据。
- `Version` 只做校验（§7.1），不参与任何逻辑、不进命名。

**与本计划的偏差（实施中发现，均已按更优方案落地）**：

1. `Resolution` 形态改变：计划里 `resolve()` 返回 `Option<Resolution>`，实施为**总是返回** `Resolution { candidates: Option<Candidates>, owner_folder: Option<String> }`。原因：`owner_folder` 与候选目录是两个独立事实，候选为空时仍要回本国基础池，合进一个 `Option` 会让两级回退的分支变复杂。
2. 新增 `drop_image()`：`pools`（精确目录）与 `recursive_pools`（递归池）是两份索引，禁重复时只摘一边会导致同一张图被重复抽出。这是**改动前就存在的缺陷**，本次修掉并加测试锁住（`pick_without_duplicates_exhausts_pool_and_excludes_used`）。
3. `layout_label()` 不再硬编码目录数：改为从 `RuleConfig::folder_lists()` 派生，新增标准四时前端文案自动跟随。
4. `generate_mapping()` 也去掉了 `config` 参数（计划只提到 `pick`/`exclude_used`）：配置已在 `for_layout` 构造规则时注入，链路上传参属冗余，`process_preserve/overwrite/generate/build_player_mapping` 一并清理。
5. P2 与 P3 合并实施：拆开后 P2 的中间态无法编译（旧 `MappingsSpec` 抽图路径与新配置类型互斥），强行拆只会制造一个跑不过测试的提交。
