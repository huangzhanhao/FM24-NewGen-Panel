设计系统 · NGM DS 1.1

适用范围：Tauri 2 + Svelte 5（runes）桌面端（Windows / WebView2，构建目标 Chrome 105+）。唯一样式入口 src-svelte/app.css，图标集中管理于 src-svelte/lib/ui/icons.ts，三语文案单点在 src-svelte/lib/text.ts。本页为 NGM DS 的唯一权威稿：界面预览（视图 A 的三个工作台）与 src-svelte 当前实现保持同步。1.1 相对 1.0 的主要演进：五步 Stepper 改为三工作台 TopNav、新增 AI 生图工作台（配置条/设置卡/画幅帧/结果画廊/灯箱/队列坞）、结果区收敛为名单/快照二 Tab、表格行高令牌化（40px）并新增勾选与「去抽图」列。

1设计语言

NewGAN Manager 是供 FM 玩家长时驻留的单机桌面工具，整体语言追求专业、冷静、可信、低打扰——像教练席的战术终端，而非炫技仪表盘或通用蓝白 SaaS。视觉上以「教练席海军蓝」深色为默认、「日间球场」浅色同期交付，两主题只是同一套令牌的不同取值；全界面只保留草坪青一个强调色，红绿琥珀仅承担语义状态。层级靠底色深浅（base / surface / raised / inset 四层，AI 画幅另有 stage 近黑舞台）、发丝描边与间距表达；装饰保持克制，反馈必须明确。

1.1 四条设计原则

原则 01

层级先于装饰

信息优先级靠间距、字重、底色层级、强调色表达；禁止渐变文字、泛光、玻璃拟态等纯装饰手段制造“高级感”。

原则 02

每个可交互元素都有完整状态

常态 / 悬停 / 按下 / 聚焦 / 禁用 / 忙碌，缺一不可（见 §7 状态矩阵）。

原则 03

单一事实源

颜色、字号、间距、圆角、阴影、动效只能引用令牌；scoped 样式只允许布局值，不得硬编码颜色与新圆角。

原则 04

安静但明确

默认低饱和、低对比装饰；操作反馈必须明确（颜色变化 ≥ WCAG AA、焦点环 3px、危险操作红色软底）。

1.2 不做什么

  • 不引入 Tailwind / Radix / 图标库等任何新前端依赖（纯 CSS + Svelte scoped；虚拟化仅用 virtua）。
  • 不做毛玻璃、彩色渐变文本、装饰性 glow、无意义卡片网格。
  • 动效时长 ≤ 200ms、位移 ≤ 8px；遵守 prefers-reduced-motion（CTA spinner 降速、骨架微光静止）。
  • 不重排既有业务流程；确认/报错继续用 Tauri 原生 dialog。不做移动端适配。

2设计令牌

令牌分三层：原始值 → 语义别名 → 组件消费。组件只允许消费语义层。:root 与 [data-theme='light'] 严格同序同组（18 个分组），新增视觉值先复用、将出现第 2 处消费时才新增令牌。

2.5 控件高度与组件尺寸

  • 常规控件 30px（--control-h）；紧凑 26px（--control-h-sm，分页器）；嵌入式迷你 24px（--control-h-xs，Key 框内提交钮、行内链接钮）。.btn 与 .btn.sm 等高（sm 只收横向内边距与字号）。
  • 表格行高 --table-row-h:40px（表头同高，两处预览表共用）：每页行数 = floor(.table-scroll 实测高 / 40) − 1，由 pagedResource.#measure ResizeObserver 推导，无行数常量。存档台下限 8 行、替换台 dense 下限 3 行。
  • 滚动条厚度 --scrollbar-size:10px；队列缩略图 --thumb-queue-size:118px；角标 --badge-size:16px / --badge-fs:10.5px。

4排版规范

  • 中文文案后接西文/数字留半角空格，由 text.ts 三语字典统一保证；zh-CN / zh-TW / en 结构同构。
  • 卡片标题、Tab 用 15px/600；品牌名 / 球员姓名才用 700。
  • 路径、UID、文件名、日志、尺寸、Seed、页码、队列计数一律等宽体；长路径在只读输入框中钉尾。
  • 省略号只用于：侧栏组名、球员姓名、状态栏日志预览、队列副行/详情、dense 姓名列（全文在 title）；按钮文字不允许截断。

5组件库规范

全局类位于 app.css，组件一文件一个并按业务域分组于 src-svelte/lib/components/：layout/（Sidebar、TopNav、StatusBar、LogDrawer）、setup/（SetupCard、RuleEditor）、replace/（ReplacePanel、PlayerViewer）、results/（RosterSnapshotTabs、PlayersTable、SnapshotPreview、TablePager）、imageai/（ImageAiPanel、ConnectionBar 内联、GenSettingsCard、SourcePlayerCard、ResultGallery、QueueDock、ProviderDialog、TemplateDialog、NumberStepper）、shared/（AvatarThumb、AvatarPopover）。支撑模块：services/（api、images）、ui/（actions、icons、dialog、Icon、pagedResource）；横切件 types.ts / text.ts / avatarBlobs.svelte.ts 在 lib 根。

7交互模式

7.1 反馈模式

  • 全局忙碌：替换期 appStore.busy 锁定写控件；轻量任务（检查完整性/扫描/读取快照）走状态栏 task 通道，结束 100% 停留 20s。
  • 破坏性操作：删 Profile、删组、补目录、覆写/未知结构继续、清空生成结果、移除队列条目、启动计费队列一律原生确认；AI 队列运行中切档/切组/删档走统一 confirmScopeChange（先取消队列，一次操作只弹一次框）。
  • 错误：单张生成失败进结果区内联错误条（结构化 GenError：类别 + userAction，可重试）；其余走 showError() 原生框；错误数红徽章挂「日志」。
  • 空态 / 浏览态：每个数据区都有引导式空态；浏览未激活 Profile 时写控件禁用并给 title 与顶部提示。

7.2 键盘与可达性

  • Tab 顺序 = 视觉顺序；自定义可点击元素（switch、排序列头、chip、灯箱）键盘可达且 Enter/Space 等价；表头 role=button tabindex=0。
  • 焦点环唯一形态：3px --focus-ring（表头焦点为内嵌双环）；禁止 outline:none 后不补环。
  • 进度条 role=progressbar + aria-value*；复选框全选用 indeterminate + aria-label；状态不只靠颜色（圆点/文案伴随）。
  • Esc 关抽屉/模态/灯箱（窗口级监听）；对比底线正文 4.5:1、大字/控件 3:1，双主题达标。

7.3 性能约束

  • 大 RTF 解析、映射、生成队列在 Rust 侧；前端分页（行数 ResizeObserver 自适应）、图片按页 blob 加载并回收；日志与大列表 virtua 虚拟滚动。
  • 队列快照节流刷新（≈120ms）；条目 uid 集合不变时跳过头像重载；宽度变化只动 transform/opacity/颜色类属性。

8实现约定（工程）

  1. 颜色/圆角/字体/阴影/动效只能用令牌；新增视觉值先加令牌；间距只允许 --sp-* 整档。
  2. 全局可复用类写进 app.css；组件特有用 scoped，scoped 中禁止硬编码颜色（:global 穿透 Icon 类除外）。
  3. 用户可见文案全部在 text.ts 三语字典；协议值（'No Profile'、'Preserve'、'queued'、排序键等）禁止入文案表。
  4. 不新增前端依赖（virtua 已是唯一新增运行时依赖）；不改 .user/ 数据结构与 config.xml 输出字节兼容。
  5. 组件外响应式状态文件名必须带 .svelte.ts（runes 编译约定）。

2标准走查环境

  • 基准窗口 1280×800 与 1440×900；断点矩阵 1440 / 1280 / 1180 / 1100 / 1024 / 900 / 560；硬下限抽检 860。
  • 三工作台都要走：存档资料（SetupCard + 全宽表）、替换（wb-split + dense 表）、AI（conn-bar + 左右栏 + 队列四态 + 灯箱）。
  • 三语各切一次（zh-CN/zh-TW/en），验证无折行截断再切回。
  • 数据态：空状态（No Profile/无组/无名单/空队列/空画廊）+ 完整态（≥3 页名单、队列四态、生成结果 ≥4 张）。

3视觉一致性检查清单

  • 令牌覆盖：app.css 外无硬编码颜色；间距只走 --sp-* 整档；同类语义同一个类。
  • 双主题切换无白闪/残影（含 stage、灯箱媒体令牌、原生 option、滚动条交汇角）。
  • 同排控件等高（30/26/24 三档不混排）；按钮文字无省略截断。
  • TopNav：当前台高亮与就绪点颜色语义不混淆；③角标计数=排队+在跑；作用域回显恒为激活档。
  • 表格：40px 行高两表一致；表头粘顶；dense 默认不横滚、拓展列横滚只在容器内；勾选列与去抽图列对齐。
  • AI 台：画幅帧比例/尺寸与参数一致（标准实绿/自定义虚绿/违规红）；队列四态胶囊色差分明；灯箱关闭钮在深/浅主题下都可见（媒体令牌）。

5交互与键盘

  • TopNav chip 任意时刻可点（就绪点不禁用）；切换工作台后队列事件不丢（订阅在 App 级）。
  • 表格全选 indeterminate、排序 Enter/Space、跳页夹取、搜索 300ms 防抖（本地分页即时过滤）。
  • 队列：启动计费 confirm、取消/移除 warning confirm、运行中切档统一护栏先取消队列；失败条「重试本条」仅可重试类别出现。
  • 灯箱：点图打开、Esc/点遮罩/关闭钮退出；画廊「再生成」带原图 size/seed。
  • Esc 关抽屉/模态/灯箱；模态脏数据切换/关闭先确认；保存按钮无修改时禁用。

7可访问性

  • 语义地标：aside/footer/ol(TopNav)/真实 table/role=dialog·aria-modal；装饰 SVG aria-hidden。
  • 进度条 role=progressbar + aria-value*；复选框与图标按钮 aria-label；状态不只靠颜色。
  • 焦点环 3px 双主题可见；Windows 125%/150% 缩放不破版；正文 AA 4.5:1。

8业务回归（真实 Tauri 窗口）

  1. 建档 → 关联组 → 设 RTF → 检查完整性（含补目录）→ 扫描RTF → 名单（搜索/排序/筛选/翻页/勾选入队/去抽图/头像气泡）→ 读取快照。
  2. 三模式替换：保留/覆写/生成各一次；单人指定替换/重掷替换/送生图；取消与完成提示。
  3. AI 生图：Key 提交（掩码不落盘）→ 单张生成（spinner/内联错误重试）→ 保存/保存并替换/同参重生/灯箱 → 名单勾选加入队列 → 启动/取消/查看单人/移除/失败重试/展开缩略图另存；运行中切档确认链路。
