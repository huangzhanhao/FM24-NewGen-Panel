### 更正（同日，按用户要求回退了上一版的 hasCache）

用户明确要求：**不要自造「缓存是否为空」的派生判据，直接照「快照预览」的写法**。已改为：

- `PlayersTable.svelte` 用 `const readable = $derived(!!appStore.lastRtfScan);`（对应快照预览的
  `readable = 展示档快照路径 === appStore.snapshotReadPath`），工具条包在 `{#if readable}` 里；
  删掉了 `hasCache` / `filtered` / 首次加载免防抖那套，空态改为与快照预览同款的三层结构
  （`!readable` → 引导空态 / 有数据 → 表格 / `else if result` → `search ? noMatchHint : emptyHint`）。
- 结论沉淀：本项目的「数据是否可读」一律用 appStore 里的全局标记（快照=snapshotReadPath，
  名单=lastRtfScan），不要从查询结果反推。副作用：只跑「替换头像」而没点过「扫描RTF」时
  （后端 rtf_cache 会被替换流水线填满，但前端 lastRtfScan 仍为 null），工具条不显示。

### 补漏：替换路径也能置「名单可读」标记

问题：`lastRtfScan` 只在 SetupCard 的「扫描RTF」里被赋值，而替换流水线结束也会写后端 `rtf_cache`
（`commands.rs` 的 `start_replace`：`*rtf_cache = result.rtf_data.clone()`），所以「只跑替换」的会话里
名单预览既没有工具条、内容也不刷新。

改法（保持「只在 store 维护标记」的机制，不回退到 hasCache）：

- `stores/app.svelte.ts` 新增全局标记 `rosterReady: boolean`（对应快照预览的 `snapshotReadPath`），
  并在 `replace:finished` 处理里按结果置位：`= e.payload.result === 'finished'`，同时 `rosterVersion++`
  触发名单预览重载；两个标记都放在 `refreshSnapshot()` 之前。
  **关键事实**：后端失败/取消时 `replace_flow::run` 返回的 `rtf_data` 是空 `Vec`，缓存会被**清空**，
  所以这两个分支必须置 false（回到引导空态），不是「保持原值」。
- `SetupCard.scanRtf` 成功后 `appStore.rosterReady = true`。
- `PlayersTable.readable = $derived(appStore.rosterReady)`；同步更新了 rosterVersion 的两处旧注释。

验证：`svelte-check` 0 errors / 0 warnings；`vitest run` 4 passed。
遗留（未处理，后端要给摘要才行）：只跑替换时 `lastRtfScan` 仍为 null → 拓展名单的随机人筛选下拉与
