1设计语言

NewGAN Manager 是供 FM 玩家长时驻留的单机桌面工具，整体语言追求专业、冷静、可信、低打扰——像教练席的战术终端，而非炫技仪表盘或通用蓝白 SaaS。视觉上以「教练席海军蓝」深色为默认、「日间球场」浅色同期交付，两主题只是同一套令牌的不同取值；全界面只保留草坪青一个强调色，红绿琥珀仅承担语义状态。层级靠底色深浅（base / surface / raised 三层）、发丝描边与间距表达，圆角人像贯穿品牌区、单人替换与空态，呼应「批量给随机人长脸」的产品心智；装饰保持克制，反馈必须明确。本节给出四条设计原则、明确的不做清单，以及六个风格维度的取舍结论。

1.1 四条设计原则

原则 01

层级先于装饰

信息优先级靠间距、字重、底色层级、强调色表达；禁止渐变文字、泛光、玻璃拟态等纯装饰手段制造“高级感”。

原则 02

每个可交互元素都有完整状态

常态 / 悬停 / 按下 / 聚焦 / 禁用 / 忙碌，缺一不可（见 §7 状态矩阵）。

原则 03

单一事实源

颜色、字号、间距、圆角、阴影、动效只能引用令牌；scoped 样式只允许布局值，不得硬编码颜色与新圆角。

原则 04

安静但明确

默认低饱和、低对比装饰；操作反馈必须明确（颜色变化 ≥ WCAG AA、焦点环 3px、危险操作红色软底）。

1.2 不做什么

  • 不引入 Tailwind / Radix / 图标库等任何新依赖（纯 CSS + Svelte scoped）。
  • 不做毛玻璃、彩色渐变文本、装饰性 glow、无意义卡片网格。
  • 动效时长 ≤ 200ms、位移 ≤ 8px；遵守 prefers-reduced-motion。
  • 不重排既有业务流程；系统对话框（确认/报错）继续用 Tauri 原生 dialog。

1.3 六维风格取舍

FM 皮肤调研得出的风格候选按 6 个维度归类后逐项定稿；未采用的候选登记为二期储备（见本节末尾）。

维度候选方向本次采用取舍依据
① 主题基调深海军蓝 ✓ / 中性炭灰 / OLED 纯黑 / 浅色明亮深海军蓝默认，浅色同期交付头部皮肤清一色深色；TinyHips 证明 OLED 纯黑可行但受众窄；FM 生态几乎没有主流浅色方案，而本工具白天也会用
② 强调色青绿 Teal ✓ / 翡翠绿 / 俱乐部色换色包 / FM 紫蓝#2DD4A7（深）/ #0DA880（浅）Material Skin 多年沿用 misty teal 且下载量第一；紫蓝被社区一致抛弃；换色包成本低，列二期储备
③ 表面与深度背景分层 ✓ / 背景图+赛事主题 / 粗边框卡片base / surface / raised 三层 + 发丝描边，仅弹层用柔和投影背景图承载氛围对观赏型游戏界面合适，对工具界面会伤可读性；粗边框卡片已被全行业淘汰
④ 造型语言中圆角 6–12px ✓ / 全直角 / 大圆角胶囊面板 10px、控件 6–8px、人像 12px 圆角矩形档案页与头像母题在 2026 仍是视觉重心，且需与面板圆角语言统一；多边形图作为辅助图形语言
⑤ 信息密度与字体13px 高密度 ✓ / 14px 舒适 / 12px 极密13px 基准 + 等宽数字 + 紧凑表格，零新增字体依赖皮肤普遍小字紧缩，但 CTRL 的前提是 1080p + Small 缩放；本工具窗口基准 1280×800、硬下限 860，取 13px 折中，靠斑马纹与等宽对齐控制长列表（30 万行级）噪声
⑥ 动效与装饰轻量 ≤200ms ✓ / 无动效 / 丰富/发光玻璃仅进度与抽屉/模态的 ≤200ms 过渡，禁用渐变文字、玻璃拟态与发光皮肤社区普遍克制（去渐变、去发光、去圆底头像）；其余界面不动

六项采用值合起来即定稿组合：深海军蓝底 + 单一青绿强调 + 三层背景深度 + 中圆角与圆角人像 + 13px 高密度 + 200ms 内轻动效，与 2026 年社区实际选择一致。深色与浅色只是同一组设计令牌的不同取值，切换主题不改变任何结构、密度与信息层级。

i

落选候选的去向（二期储备）：①强调色换色包（Darkside blue/red/green bundle、AnSeOs Emerald Green 的做法，令牌化后成本很低）；②OLED 纯黑主题（TinyHips 路线，只需再补一档 --bg-* 取值）；③低分辨率/更小字号档（MNB 与 Material 的低分屏布局、CTRL 的 Small 缩放前提，暂以 13px + 860 宽度硬下限断点兜底）。

  • 进度条宽度过渡 150ms linear；忙碌呼吸点 1.3s 循环（状态指示，不属于装饰动效）。

2.8 层级 z-index

遮罩 --z-overlay:40 / 抽屉与模态 --z-modal:50 / 头像气泡捕获层 --z-popover:1000 / 气泡本体 --z-popover-top:1001。新浮层必须在 --z-* 尺度内取值，禁止随手写魔法数。

2.9 响应式断点（桌面窗口）

断点行为
≥1280px（基准）侧栏 248px，内容 padding 10/16，路径行三列
≤1180px侧栏 224px；模式说明允许折行；侧栏脚注收成 2×2
≤1024px侧栏 212px；步骤条连接线收窄到 20px，允许优雅换行
≤900px侧栏 200px；内容 padding 收为 10/12；模式分段控件占满整行、说明移到下一行；单人替换卡头部提示折到下一行
硬下限窗口 minWidth 860；低于此宽度仅保证无横向滚动、不重叠；不做移动端适配

宽内容（拓展名单 18 列）始终由 .table-scroll 内部横向滚动吸收，页面级永不出现横向滚动条。

!

窗口尺寸约束落在 src-tauri/src/lib.rs 的编程式建窗（inner_size(1280,800)、min_inner_size(860,600)）。该窗口必须代码创建（.data_directory() 把 WebView2 数据便携化），禁止在 tauri.conf.json 声明 windows，否则会建出两个 label 为 "main" 的 webview 导致 panic。

LogDrawer（左侧滑入）/ Modal / Popover 浮于布局之外
  • 根布局：display:grid; grid-template-columns:248px minmax(0,1fr); grid-template-rows:1fr auto; height:100vh（主列必须 minmax(0,1fr)，裸 1fr 会被宽表撑开，见下）。
  • 只有 .content 与卡片 .card-body / .table-scroll 可滚动；body{overflow:hidden}。
  • 滚动容器必须 min-height:0，否则 flex 子项撑破布局。
  • 宽度约束链（横向）：主列定义为 minmax(0,1fr)（不能裸写 1fr——其 auto 最小值会被宽内容撑开）；.content / .card / .card.grow / .card-body / .table-toolbar / .table-scroll 与结果区根 .table-pane 全部补 min-width:0。这样拓展名单 18 列宽表首次挂载时宽度即在 .table-pane 层被截断，超宽只在 .table-scroll 内横向滚动，不撑开网格列或页面（页面级永不出现横向滚动条）。

4排版规范

  • 中文文案后接西文/数字时留半角空格（如「扫描 RTF」「共 12 条」），由 text.ts 统一保证。
  • 标题不加粗到 700（卡片标题 600）；品牌名 / 大 UID 才用 700。
  • 一段说明只用一个弱化层级（text-3），不叠加「小字 + 浅色 + italic」。
  • 路径、UID、文件名、日志一律等宽体；长路径在只读输入框中钉住尾部。
  • 省略号只用于：侧栏组名（单行）、状态栏日志预览、气泡标题；按钮文字不允许截断（见 §5.1）。

5组件库规范

全局类位于 app.css，组件一文件一个并按业务域分组于 src-svelte/lib/components/：layout/（Sidebar、Stepper、StatusBar、LogDrawer）、setup/（SetupCard、RuleEditor）、replace/（ReplacePanel）、results/（ResultsSection、PlayersTable、PlayerViewer、SnapshotPreview、TablePager）、shared/（AvatarThumb、AvatarPopover）。支撑模块分置于 lib/services/（api、images——Tauri 边界）与 lib/ui/（actions、icons、dialog——表现层）。状态命名：默认 / :hover / :active / :focus-visible / :disabled / .active（选中）/ .busy。

7.2 反馈模式

  • 全局忙碌：后端任务期间 appStore.busy 锁定一切写操作按钮；底部状态点琥珀呼吸 + 迷你进度条（n/total · %）+ 阶段文案；任务结束 100% 停留 20s 再清，避免闪烁。
  • 进度：可数阶段显示「当前/总数」，纯阶段锚点只显示百分比；进度数字 tabular-nums。
  • 破坏性操作：一律 Tauri 原生 ask 确认（删 Profile、删组、补目录、覆写/未知结构继续），文案含对象名/路径；无例外。
  • 错误：命令失败走统一 showError() 原生 message 框；日志抽屉可查；错误数以红色徽章挂在「日志」按钮上。
  • 浏览态 / 空态：未激活 Profile 时写控件禁用并在 title 与 Stepper 提示；每个数据区都有引导式空态，说明「做什么动作才能看到数据」。

7.3 键盘与可达性

  • Tab 顺序 = 视觉顺序；所有自定义可点击元素（switch、排序列表头等）必须键盘可达且 Enter/Space 可触发。
  • 焦点环唯一形态：3px --focus-ring；禁止 outline:none 后不补环。
  • 图标按钮必须有可读名称（title + 必要时 aria-label）；装饰 SVG aria-hidden。
  • 弹层：Esc 关闭、点遮罩关闭（脏数据先确认）、模态 aria-modal。
  • 对比底线：正文 ≥ 4.5:1，大字/控件边界 ≥ 3:1；两主题均须满足。
  • prefers-reduced-motion: reduce 时全站 animation/transition 归零（全局媒体查询已内置）。

7.4 性能约束

  • 大 RTF 解析、表格数据均在 Rust 侧；前端表格分页（每页 8 条），图片按页加载并回收 blob URL；日志用虚拟列表。
  • 动效只动 transform/opacity（白名单见 §2.7），不得在动画中触发布局。
  • 列表悬停过渡只允许 background/color/border；大 RTF 不打逐行 DEBUG 日志。

2标准走查环境

  • 基准窗口：1280×800（FM 玩家常见窗口）与 1440×900（设计基准）。
  • 断点矩阵宽度：1440 / 1280 / 1180 / 1024 / 900；硬下限抽检 860。
  • 主题：深色（默认）、浅色，每个宽度都要切一次。
  • 数据：分别用「空状态（No Profile、无组）」「完整状态（激活档+组+RTF+扫描后名单 ≥3 页）」两份数据走查；拓展名单（18 列）单独检查表格横滚。
  • 纯浏览器（vite dev，无 Tauri）只能验证静态外观与布局；凡涉及对话框/文件选择/IPC 的交互必须在 tauri dev 真窗口复验。

3视觉一致性检查清单

3.1 令牌与样式卫生

  • 新增颜色/圆角/阴影/字号/动效全部以令牌表达，app.css 外无硬编码颜色（scoped <style> 同此要求）。
  • 没有引入新依赖；没有出现 Tailwind/内联 style 承载视觉值（动态 width:% 等运行值除外）。
  • 同一语义在各处只用同一个类：主操作 = .btn.primary，危险 = .btn.danger，开关 = .switch，分段 = .seg3，页签 = .seg-tabs。
  • 字级只出现在 --fs-* 档位内；路径/UID/日志为等宽体。
  • 控件高度符合 30/26/约 40 三档（常规 / 紧凑 / 主 CTA）；同排控件等高。
  • 图标全部取自 lib/ui/icons.ts，线性 24×24/stroke 2，尺寸只用 12/14-15/28 三档。

3.2 双主题

  • 切换主题无白闪、无残留（侧栏、卡片、输入框、表格、弹层、气泡、滚动条、原生 option）。
  • 每种语义色在其背景上达到对比度：正文 ≥ 4.5:1；text-3 大字/辅助 ≥ 3:1（占位符允许略低但不得低于 3:1）。
  • 焦点环在两种主题下都清晰可见。
  • 浅色主题无“深色残影”：深色专用 rgba/阴影在浅底下不发灰、不刺眼。

3.3 层级与布局

  • 画布 → 卡片 → 浮层的层级一眼可分（surface/elevation/遮罩各司其职）。
  • 卡片间距统一；对齐基线：标签列 78px 右对齐、路径行三列不跳变。
  • 页面级无横向滚动条；宽表格只在 .table-scroll 内部横滚，表头粘顶有效。
  • 长路径在只读框中钉尾显示；省略号只出现在允许清单（组名、状态栏日志、气泡标题），按钮无截断。
  • 文本不重叠、不被图标/徽章压住；中文与西文之间留空格。

3.4 状态外观

逐控件目视六态：常态 / 悬停 / 按下 / 聚焦 / 禁用 / 选中或忙碌。

  • 主 CTA 禁用态中性化，不像“可点的深色大按钮”。
  • 危险操作悬停出现红色软底/红边，常态安静。
  • 表格悬停行、当前组、选中分段/页签的“选中语言”互不混淆（绿色软底=选中，行悬停=中性 raised）。
  • 空态有引导动作文案与图标，不用空白或裸破折号铺满。

5.2 反馈与等待

  • 点击「检查完整性/扫描头像/扫描RTF/读取快照」立即有反馈：状态栏任务名 + 进度条，结束 100% 停留可见。
  • 替换中：主按钮变「替换中…」、取消可用、其余写操作全部禁用；阶段文案与百分比实时更新；结束弹结果框。
  • 失败路径：后端报错走原生错误框 + 日志可查 + 日志按钮红色错误计数；忙碌态必定复位（不卡死）。
  • 悬停反馈 ≤120ms 出现；按钮按下有 0.5px 按压；无“点了没反应”的控件。
  • 300ms 搜索防抖存在（连续输入不产生逐字请求）；翻页/切组后旧响应不回填（令牌/缓存失效机制）。

5.3 文案与引导

  • 所有空态说明“做什么动作能出数据”（引导式空态）。
  • 浏览未激活 Profile：顶部步骤条提示 + 写控件 title 解释 + 主 CTA 禁用原因明确。
  • 图标按钮必有 title；危险按钮 title 说明后果；无英文调试文案残留。
  • 完整性结果三态（完整/可修复/无法识别）胶囊 + 详情 + 动作同时可见。

5.4 鼠标与触控板

  • 表格行悬停、组条目悬停、链接悬停区域与可点区域一致（不留“看着能点其实点不到”的缝）。
  • 气泡：悬停延迟 160ms 关闭、移入气泡不关、点击钉住、点外部/Esc/再点关闭。
  • 自定义滚动条在深/浅主题均可见但不抢眼。

6动效标准

  • 时长白名单：120 / 140 / 150 / 160 / 180ms；任何新动效 ≤200ms。
  • 位移白名单：气泡 4px、抽屉/模态 8px；按压 0.5px；其他动效不位移。
  • 只允许动 opacity / transform / background-color / border-color / color / box-shadow；进度条动 width 属既有例外。
  • 开启系统「动画效果关闭」（或 DevTools Emulate prefers-reduced-motion: reduce）后：弹层、呼吸点、按压、开关全部静默化，功能不受影响。

7可访问性（A11y）核对

  • 对比度 AA：正文 4.5:1、大字/控件边界 3:1（两主题各测一次，可用 DevTools 拾色器）。
  • 语义：侧栏 <aside>、状态栏 <footer>、步骤用 <ol>、表格用真实 <table>/th/td、弹层 role=dialog aria-modal。
  • 装饰 SVG aria-hidden；图标按钮有 aria-label/title；状态不只靠颜色（成功/警告带圆点或文案）。
  • 读屏顺序与视觉顺序一致；徽章、进度有文本伴随（如 40% · 阶段名）。
  • 字号放大到 125%/150%（Windows 缩放）布局不破、不截断。

8业务回归（真实 Tauri 窗口）

i

UI 改版不得改变业务流；以下三条主流程每次发版走一遍。

  1. 建档 → 关联组 → 设 RTF → 检查完整性（含补目录）→ 扫描 RTF → 名单预览（搜索/排序/筛选/翻页/头像气泡）。
  2. 三模式替换：保留/覆写/生成各一次（可用测试 RTF）；验证进度、取消、完成弹窗、快照预览自动可读。
  3. 危险操作：删组确认、删 Profile（激活档/未激活档/No Profile 三态）、规则编辑脏数据切换/关闭确认、非法 JSON 保存被拒。
