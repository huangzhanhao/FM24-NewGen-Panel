# NewGAN Manager

> 给 Football Manager 的 NewGAN / 随机人批量匹配头像（facepack）的桌面工具。
> 读取 FM 导出的 RTF 名单 → 按「国籍 + 种族」自动挑一张头像图片 → 生成 FM 能识别的 `config.xml`。

![Tauri Build](https://github.com/huangzhanhao/NewGAN-Manager-ByHzH/actions/workflows/tauri.yml/badge.svg)

**当前版本 v2.0.0** ｜ Fork 自 [Maradonna90/NewGAN-Manager](https://github.com/Maradonna90/NewGAN-Manager)（上游已停止维护）｜ v2 基于 **Tauri 2（Rust 后端）+ Svelte 5（前端）** 重构：无需 Python / .NET 运行时，大名单（30 万行级）不卡顿，界面按操作旅程重排。

---

## 它解决什么问题

NewGAN（随机人）默认没有头像。手动给成百上千名随机人一张张贴图不现实。这个工具把 FM 导出的球员名单（RTF）和一套按种族分目录的头像包对应起来，**批量**生成 FM 读取的 `config.xml`，让随机人自动"长脸"。

**典型使用一句话：** 导出 RTF → 选头像包目录 → 点 `替换头像` → 回 FM 重载皮肤。

## 主要功能

- **多 Profile / 组管理**：不同存档各建一套 Profile；一个 Profile 下可关联多个头像包目录（组），每组独立记录 RTF 与映射快照。下拉切换先进入「浏览预览」，点 **激活** 才真正切档——把当前 `config.xml` 存回旧档快照、再把目标档快照写回头像包目录；新建 Profile 则建好即激活。启动固定从缺省档 `No Profile` 开始，不自动恢复上次激活的档。
- **多导出格式自动识别**：基础名单 / 拓展球员 / 拓展职员三类列结构 × 中英文两种数据语言自动识别，归一到同一份球员记录；国籍显示文本经 `nat_translation.json` 翻译回英文三字码再查种族映射——**无需把 FM 切成英文**。
- **只处理随机人**：`仅随机人` 开关按随机人标记（UID 的 `r-` 前缀）过滤——基础名单全员随机人，拓展名单按第 10 列 `Newgen` 标志（`是/否`、`Yes/No`）判定——只给随机人换脸，被过滤者不写入 `config.xml`。
- **三种替换模式**：`保留`（Preserve）保留已换过的只补新的；`覆写`（Overwrite）对名单内球员全部重抽、名单外保留；`生成`（Generate）无视现有 `config.xml` 从零生成——本档档景里已有映射时，发起前会先弹一次「将清空现有 N 条」的确认（详见[执行面板](#4-执行面板选模式与开关后执行)）。
- **名单预览**：执行「替换头像」或「扫描RTF」后展示最近一次解析结果，分页预览表支持排序 / 搜索；数据保留在 Rust 侧，前端只取当前页，大名单也不卡。
- **头像扫描与索引缓存**：点 `扫描头像` 遍历头像包并缓存图片索引，摘要（图片总数、命中的标准）写入日志。索引按「头像包根目录 + 目录签名」缓存——签名由各一级目录的名字、mtime 与直接子条目数组成，只反映**会影响抽图池**的改动；扫过一次且内容没变，之后每次替换都直接复用，不再重扫。详见[性能与缓存](#性能与缓存)。
- **单个球员微调**：结果区切到 `单人微调`，输入 UID 回车 → 预览当前头像与球员信息 → 选一张图点 `替换`，只改写这一条映射。
- **AI 生成头像**（可选，需自备 API Key）：独立工作台。顶部一条配置条（服务商 / 模型 / Key / 状态灯）；左栏是**单个球员**的档案卡，把年龄、位置、种族、肤色、发长、发色、身高、俱乐部、CA、PA 逐项列出来——扫一眼就知道提示词变量会不会填错；右栏按该球员渲染提示词正文（可编辑）+ 依**模型能力集**显隐的参数区 + 结果画廊。多人走名单工具行的 `加入队列`，队列坞常驻台底、顶栏 ③ 上有数量角标。服务商支持 OpenAI 兼容协议与阿里云百炼（DashScope），各自可用的参数与尺寸约束由服务商按模型声明。
- **规则可视化编辑**：`规则配置` 对话框直接查看、修改并保存标准规则 json（国籍→目录映射、FolderList 等），保存时自动做结构校验。
- **自动备份**：每次写入 `config.xml` 前生成 `config_backup_YYYYMMDD-HHMMSS.xml`，每个头像包目录最多保留最近 5 份；覆盖**档景快照**（`.user/<存档>/` 下）前同样先备份旧的 `<快照词干>_backup_...xml`，每份快照也最多保留最近 5 份——档景是「保留/覆写」模式的判据源，写坏了没有第二份可对照。早期版本备份名为 `config备份_...`，这类历史文件不会被计入或清理，可手动删除。
- **进度与取消**：解析 / 扫盘 / 映射 / 写文件全部在 Rust 后台线程执行，扫盘按一级目录并行，进度经事件流推送；执行中界面保持流畅，可随时 `取消`。
- **应用内日志**：状态栏常驻状态与迷你进度，`日志` 按钮带错误角标；抽屉内可按级别筛选、只看某一级、一键打开日志文件；日志文件 10 MB × 3 份滚动。
- **完整性检查与一键创建**：`检查完整性` 按规则 json 的目录清单判定头像包归属哪个标准、缺哪些目录，缺失时一键批量创建（执行替换前仍兜底校验）。

## 快速开始（普通用户）

1. 到 **Releases** 下载对应平台安装包，安装运行（无需安装 Python / .NET）。
   - **Windows**：`NewGAN-Manager_2.0.0_x64-setup.exe`（NSIS，安装到当前用户目录，无需管理员权限）。
   - 系统使用自带 WebView2（Win10 1809+ / Win11 一般已内置）；若缺失，安装包会联网引导安装。
   - **首次运行提示**：应用未购买代码签名证书，Windows SmartScreen 或部分杀毒软件可能弹出警告（"Windows 已保护你的电脑"）。请点 **「更多信息」→「仍要运行」**；如在杀软信任区添加应用目录可避免反复提示。应用源码完全公开，可自行审计。
   - **macOS / Linux**：下载 CI 构建的对应平台产物。
2. 把仓库里的 `views/`、`filters/` 两个文件夹复制到 FM 用户目录：
   - Windows：`文档\Sports Interactive\Football Manager 20XX\`
   - macOS：`~/Library/Application Support/Sports Interactive/Football Manager 20XX/`
3. 按下面的[使用流程](#使用流程)操作。

## 使用流程

> 界面骨架（侧栏 / 顶栏三工作台 / 状态栏）与跨台约定见[界面结构与交互约定](#界面结构与交互约定)；本节按操作顺序走一遍。

### 1. 在 FM 中导出 RTF
安装 `views/` 后，在 FM 里使用 **`SCRIPT FACES`** 的 `player search` / `squad` / `shortlist` / `staff` 视图（配合 `filters/` 里的 `is newgen search filter` 只看随机人），把列表**另存为 RTF**。

扫描时**以表头为识别依据**（表头是导出视图列结构的正式说明，判断出错能精确指出是哪一列）：先看列数（7 列 = 基础名单，≥18 列 = 拓展名单，8-17 列直接判不合法），再依次核对前 4 列为「编号 / 国籍 / 第二国籍 / 姓名」；拓展名单还要求第 10 列为「是新生球员」，并按第 15 列是「所在地」还是「偏好工作」区分球员 / 职员。表头判断后会抽查前 20 条数据行，至少 1 条合法才放行，避免表头与数据行错位的文件被悄悄解析成空名单。数据语言不看表头（英文拓展名单的表头是中英混排的），而是拿数据行的国籍值查翻译表：命中哪个语言节点就判为哪种语言，国籍已是三字码时默认英文。共支持 **6 种组合 = 3 种列结构 × 2 种语言**：

| 格式 | 列数 | 列序（1 起） |
| :--- | :--- | :--- |
| 基础名单（球员/职员通用） | 7 | `UID \| 国籍 \| 二国籍 \| 姓名 \| 发长码 \| 发色码 \| 种族码`（视图本身按 is newgen 过滤，全员按随机人处理） |
| 拓展球员名单 | ≥18 | `UID \| 国籍 \| 二国籍 \| 姓名 \| 发长码 \| 发色码 \| 种族码 \| 肤色码 \| 头像 \| Newgen \| 性别 \| 年龄 \| 身高 \| 俱乐部 \| 所在地 \| CA \| PA \| R.C.A`（第 9 列头像为 FM 图片列，导出为空文本；第 19 列起为用户自定义列 `extraFields`） |
| 拓展职员名单 | ≥18 | 列序同拓展球员，仅第 15 列为「偏好工作」（球员名单此列为「所在地」） |

合法性行级校验针对 UID（4-10 位数字）、国籍/第二国籍（必须是 `nat_translation.json` 收录的显示文本或 `nat_codes.json` 收录的国籍码）、种族码（0-10）、肤色码（0-19）、发长码（0-5）、发色码（1-19），R.C.A 非空时须为数字；第二国籍、肤色、R.C.A 允许留空（FM 对未加载对象会导出空白）。国籍查不到的行**整行丢弃**并记警告日志（可据日志增补翻译表），其余不合法行同样跳过；逐行跳过日志最多记 50 条，超出合并成一条汇总。整份文件不合法时弹「RTF 格式不合法」：表头问题精确到「表头第 N 列」，数据行问题定位到「第 N 行「字段」」。旧版 14 列详细名单、性别在第 3 列的旧职员拓展布局已不再支持。

示例（基础 7 列）：

```
| UID       | Nat  | 2nd Nat | Name        | 头发长度 | 发色 | 种族码 |
| 2000472008| ESP  | USA     | Pepe Sáenz  | 1        | 12   | 1      |
```

> 随机人判定：基础名单没有标志列，UID 一律加 `r-` 前缀（全员随机人）；拓展名单看第 10 列 `Newgen`（`是/否`、`Yes/No`），为「是/Yes」时 UID 加 `r-` 前缀，否则保留纯数字 UID。`仅随机人` 开关按 `r-` 前缀过滤，两种格式都可用。

### 2. 侧栏：浏览、激活 Profile 与头像包（组）
- 启动固定停在缺省档 **`No Profile`**（未激活，不可删除）；上次会话激活了哪档**不会**自动恢复。
- **下拉框选择任意存档 = 浏览预览**：可以查看该档的组配置与 RTF 设置，但关联头像包、切换组、设置 RTF、执行替换等改动型操作置灰，提示「请先点击激活」。
- 点蓝色 **`激活`** 按钮才真正切档：旧档各组 `config.xml` 存回快照、新档快照恢复到头像包目录。已激活时按钮变灰，激活状态由按钮本身表达（无单独的状态标签）。
- 点 `存档资料` 区的 ＋ **新建 Profile**：输入名称创建，**建好即自动激活**（同名档不得重建覆写）。
- 红色 **`删除当前 Profile`** 删除**下拉选中**的存档及其全部组配置与映射备份；若删的是激活档，自动回到 `No Profile`。
- 点 `头像包（组）` 区的 ＋ **关联头像包根目录**（其下是 `African`、`Asian`… 等种族子目录），一个 Profile 可关联多组；点组名切换当前组，组条目上显示 RTF 是否已设置；行内右侧的红色 `×`（点击区上下占满整行）删除该组。以上操作均需先激活。

### 3. 「当前任务」卡：检查、扫描与设置 RTF
- 未关联头像包时，这一卡仍完整显示「头像包 / RTF 名单 / config.xml」三行路径框与按钮（路径框为空、按钮置灰并提示原因），只在下方给一行灰色提示；关联后立即刷新。
- 路径框等宽对齐，长路径默认**显示尾部**（末级目录 / 文件名），鼠标悬停可看完整路径。
- **`检查完整性`**：按规则 json 的 `FolderList` 识别头像包归属哪个标准并校验目录是否齐全；缺失时 **`一键创建缺失目录`**；无法识别时提示替换时将递归全池随机（可在 `规则配置` 调整标准目录清单）。切换组/切档后检查结果自动重置。
- **`扫描头像`**：遍历头像包并缓存图片索引（摘要写入日志），同时记下目录签名；替换时优先复用这份缓存，命中就跳过扫盘。
- **`选择RTF`** 挑选 FM 导出的 RTF 名单；**`扫描RTF`** 立即解析并填充名单预览（结果写入日志）。
- **config.xml 行**：`查看config` 打开 config.xml 所在目录；`查看快照` 打开存档 XML 快照所在目录。
- **`规则配置`**：打开规则编辑对话框，直接修改并保存标准规则 json。
- 浏览态（未激活）下 `选择RTF` 等改动型操作置灰并提示先激活；检查、扫描类操作不受限。

### 4. 执行面板：选模式与开关后执行
- **模式**：`保留` / `覆写` / `生成` 三个 chip 任选（对应 Preserve / Overwrite / Generate，含义见[主要功能](#主要功能)）。
- 开关（`选项设置：` 行）：`允许复用图片`（关闭时保留模式会先剔除 `config.xml` 已用图片）、`仅随机人`、`写入前备份`。
- 未就绪时按钮禁用并提示缺什么（选择 Profile · 选择头像包 · 设置 RTF 名单）；浏览态下提示替换只作用于已激活的存档。
- **发起前两道确认**：① 完整性兜底校验（缺目录 / 结构无法识别时问一句）；② **既有映射预检**——只有 `生成` 模式可能把本档映射写成空表（`保留`、`覆写` 都携带既有条目），本档档景非空时状态栏先显示「检查既有映射」，再弹「将清空本档现有 N 条映射」确认。没点确认的这一轮，Rust 侧的写前拦截会直接中止（`config.xml` 与档景都不动，多为名单被筛空或包里没有图）；点过确认后才会真的写出空表。想清空 `config.xml` 就走这条：选 `生成` → 确认。
- 点击 **`替换头像`**，进度条与状态文字实时推进，执行中可 `取消`，完成弹出 `替换完成！`。头像包索引命中缓存时直接进入映射阶段（日志写明「命中（复用，不扫盘）」），未命中或目录内容已变则现场重扫。

### 5. 结果区：名单预览与单人微调
- **名单预览**：最近一次解析结果（替换头像或扫描RTF 产生）分页表格，可排序 / 搜索。
- **单人微调**：输入该球员 UID 回车 → 查看当前头像与球员信息 → `浏览` 选一张新图（路径需形如 `...\<种族目录>\<图片名>.png`）→ **`替换`**，仅改写这一条映射。字段较多，窗口较窄时会自动换行，无需拖动横向滚动条。

### 6. 回 FM 生效
`偏好设置 → 界面` 中**取消再勾选皮肤、重新加载皮肤缓存**（Reload skin cache），必要时清缓存后重启 FM。

### 7. 状态栏与日志
底部状态栏常驻显示当前状态（就绪 / 进度文字）与迷你进度条；`日志` 按钮出现红色角标表示有错误，点开抽屉可按级别筛选、只看某一级、打开日志文件或清空显示。

> 进度有**两条独立通道**：替换流水线走 `replace:progress`，「检查完整性 / 检查既有映射 / 扫描头像 / 扫描RTF / 读取快照」这类扫描走 `task:progress`。两条通道的载荷形状一致（状态文案 + 百分比 + 计数），状态栏统一渲染，同一时刻只显示一条（替换优先）。任务跑完后 100% 会在状态栏停留约 20 秒再自动清空，避免一闪而过看不到结果。

> 日志管道基于官方 `tauri-plugin-log` 插件（log 门面 + 控制台 + 10 MB × 3 份滚动文件，依赖库日志同样汇入）；抽屉列表来自 Rust 侧的环形缓冲（上限 1 万条，仅本次运行）：前端启动时会先向 `query_logs` 回填一次历史，再订阅 `log:batch` 增量。
> 因为启动日志（`Starting Application v2`）在 WebView 开始加载页面前就已被 emit，而 Tauri 不重放事件，所以这一行只能靠回填拿到。

## 界面结构与交互约定

窗口基准 1280×800（`src-tauri/src/lib.rs` 的 `inner_size`；可拖动，下限 860×600）。整体按「**左列选作用域，顶栏选动作**」组织：

```
┌──────────────┬──────────────────────────────────────────────────┐
│ 侧栏 = 作用域 │ 顶栏  ①存档资料 ─ ②批量/单人头像替换 ─ ③AI生成头像 │
│ 存档 / 组管理 │      （chip 可自由切换，右侧状态点 = 就绪度）      │
│              │                            右端：档 X · 组 Y     │
│ ──────────── │                                                    │
│ 主页 / 教程  │ 当前工作台（内容区 ≈1000px）                       │
│ FAQ / Discord├────────────────────────────────────────────────────┤
│              │ 状态栏（只占内容列，不伸进侧栏）                    │
└──────────────┴────────────────────────────────────────────────────┘
```

### 三个工作台

| # | 工作台 | 里面有什么 |
| :--- | :--- | :--- |
| ① | **存档资料** | 头像包 / RTF / config.xml 三条路径 + `检查完整性`、`扫描头像`、`扫描RTF`、`一键创建缺失目录`；标准规则入口。下方**验证视图**：全宽 18 列名单预览 / 快照预览 |
| ② | **批量/单人头像替换** | 左栏 320（写）：模式 chip、选项开关、`替换头像` 进度按钮、**单人微调常驻**；右栏（读）：名单 / 快照结果视图 |
| ③ | **AI 生成头像** | 顶部全宽配置条（服务商 / 模型 / Key / 状态灯）；左栏单人档案卡；右栏提示词正文 + 参数区 + `生成图片` + 结果画廊；台底全宽队列坞 |

②③ 的左右分栏是**读写分离**，不是子 Tab：单人微调与批量替换同为写操作、名单与快照预览为读操作，按读写分栏语义更干净，也让单人微调不必「从名单行下钻再返回」。① 不放单人微调（写操作归②）、也不放 AI 服务配置（归③），保持「看清手里有什么料」。

### 顶栏状态点（三档）

| 色 | 含义 | 判据 |
| :--- | :--- | :--- |
| 绿 | 开工条件齐备 | ① 已激活档 + 已选组 + 已设 RTF + 快照已读　② `replaceReady` 三条件全满足　③ 已设 Key + 已选模型 + 名单可读 |
| 琥珀 | 最小前提已有，缺 1–2 项 | 点进去看就绪提示补 |
| 灰 | 最小前提都不存在 | 基础条件未建立 |

**状态点从不禁用 chip** —— 禁用等于把用户锁在外面，点进去才知道差哪一项。chip 之间的连接线表达「顺序」：它之前的台全部就绪才点亮。**「我在哪」（chip 高亮）与「我该做啥」（状态点 + 连接线）分开说**，所以停在 ③ 时若配置未就绪，①② 之间的线不会全亮。

### 名单 / 快照预览的两处分工

同一份组件两处用，列集按职责分化：

| | 存档资料台 | 替换台右栏 |
| :--- | :--- | :--- |
| 宽度 | 全宽 ≈940px | 窄栏 ≈670px |
| 列 | **完整 18 列** | **精简列集**（勾选 / UID / 姓名 / 头像 / 年龄 / 所在地 / 送生图），次要列可勾选展开 |
| 职责 | 审阅名单（扫完 RTF 就地验证） | 看执行结果 |

列集切换用 prop（`dense`）而非视口断点：同一个窗口里两处容器宽度不同，视口宽度一样但可用列不一样。

### AI 队列与作用域

队列条目隐含绑定**入队时**的「档 · 组」——提示词按该档球员信息渲染、产物落进 `<组>/_generated/`。因此：

| 情况 | 处理 |
| :--- | :--- |
| 队列**空闲**时切档 / 切组 / 关联头像包 / 新建档 | 不打扰，直接切 |
| 队列**运行中**做上述任一操作，或**空闲时**删档 / 删组 | 弹一次确认「继续将取消未完成的生成任务」；确认 = 取消队列后执行，取消 = 留在原作用域 |
| 启动队列时 | 不再校验条目作用域 |

- 队列是**会话内存态**（与 Key 一样不落盘），重开应用即空，不存在跨会话的归属问题。
- **一次操作只弹一次**：删除确认与队列警告合并在同一个对话框里（`Sidebar.svelte` 的 `confirmScopeChange` 统一处理，全文件只有那一处 `ask(`）。空闲时的删除也会问一句——删除不可逆。
- 护栏是「显示」而非「打断」：队列坞标题行常驻「入队时 档 X · 组 Y」，顶栏右端常驻作用域回显，两处对齐即可看出这批是在哪个档组入的队。
- 切到别的台，队列进度看顶栏 ③ 的数量角标；**队列进度不进状态栏**——状态栏只有内容列宽，且已有替换 / 任务两条进度通道。

### 响应式断点

| 断点 | 行为 |
| :--- | :--- |
| ≤1180 / 1024 / 900 | 侧栏与内容列的全局收缩档（`app.css`） |
| ≤1100 | 替换台 `.wb-split` 退化为上下堆叠（写在上、读在下） |
| ≤1024 | AI 台两栏改纵排 |
| 容器 ≤360 | 替换面板内部纵向堆叠（`@container`，判的是**容器**宽度） |

> 900–1100 区间出现「整体已堆叠、替换面板内部仍横向」是**正确行为**：堆叠后它变全宽，横向放得下，别当 bug 修。窄栏适配必须用 `@container` 而非视口断点——面板的永久归宿是 320px 窄栏，但堆叠后是全宽，视口宽度区分不了这两种容器宽度。

## 性能与缓存

替换流水线一共五步：解析 RTF → 扫盘建索引 → 抽图映射 → 写 `config.xml` → 同步快照。其中**扫盘建索引是绝对大头**，所以优化都围着它做，原则是「结果逐字节不变，只是更快」：

| 环节 | 优化前 | 优化后 |
| :--- | :--- | :--- |
| 头像包扫描 | 单线程，每条目多一次 `metadata` 系统调用 | 一级子目录**并行**扫描 + 用目录项自带的类型判定 `DirEntry::file_type()`，省掉那次调用 |
| 索引复用 | 每次替换都重扫整包 | 按**目录签名**（各一级目录的名字 / mtime / 直接子条目数）比对缓存，命中直接复用 |
| 快照同步 | 收尾把快照重新解析一整份 XML | 收尾直接用本次映射结果填充预览缓存（有「往返恒等」单测守门） |
| `config.xml` 读取 | 两趟正则 | 单趟扫描 + 按记录标记计数，路径用 `rsplit_once` 拆分 |
| 抽图取图 | 每名球员在池上 O(idx) 线性游走 | 池改为「排序去重 `Vec` + `swap_remove`」，取图 O(1) |

**实测**（标准三、28 万图头像包、1599 名球员，同一存档连续替换；数据取自 `data/newgan.log`）：

| 阶段 | 优化前 | 优化后（首次 / 命中缓存） |
| :--- | :--- | :--- |
| 头像包索引 | 14.6 s | 0.155 s / 0.024–0.027 s |
| 逐球员抽图 | 0.243 s | 0.022 s |
| 同步存档快照 | 1.4–1.5 s | 0.033–0.042 s |
| 收尾（写缓存 + 快照同步） | 1.5 s | 0.216 s / 0.074–0.085 s |
| **总耗时** | **16.5–16.6 s** | **1.4–1.5 s** |

差值主要来自「抽图池顺序」与「扫盘方式」两处：旧实现每名球员都要在池里线性走到第 idx 张图（平均几百步），并且每个目录条目都额外问一次文件系统「这是不是目录」；新实现把池改成可 O(1) 取用的去重数组，扫盘按一级目录并行、目录类型直接取目录项自带的答案。

**跨平台注意**：目录判定统一走 `facepack_scanner::entry_is_dir` —— 先看目录项自带的类型，是符号链接再回读一次确认；拿不到类型信息时回退 `Path::is_dir()`。这样「符号链接指向目录」的头像包（macOS / Linux 上常见）不会被误判成文件而让整棵子树从池里消失，Windows 的 junction 也照常识别。目录签名里的 mtime 在各文件系统上精度不同（NTFS 精确到 100 ns，FAT32 / 部分网络盘只到 2 s），但签名只用来判断「能不能复用缓存」，即使判断偏保守（多扫一次）也不会写错结果。

> 逐阶段耗时与优化点的完整记录已随旧方案文档一并清理，上表即结论；日常排查直接看 `data/newgan.log`——流水线每一步都会打印耗时。

## 头像包标准与抽图规则

程序扫描头像包根目录后自动判定它属于哪个「标准」，再用该标准配套的抽图模型给每名球员选图。一个标准 = 一套目录组织约定 + 一份规则 json + 一个抽图模型，三者互不干涉。

| 标准 | 包结构 | 抽图逻辑 | 规则文件 |
| :--- | :--- | :--- | :--- |
| 标准一 | 图片直铺在根目录，无子目录 | 完全随机（忽略国籍与种族码） | 无（没有可配数据） |
| 标准二 | 14 个种族/大区目录 | 国籍查表 → 种族码修正 → 目录池随机 | `standard2.json` |
| 标准三 | 细分目录（国籍级 + 族群级，62 个图像池） | 规则块检索（见下） | `standard3.json` |
| 无法识别 / 空包 | 目录名与任何标准的清单都不构成包含关系 | 递归全池随机（包内所有子/孙目录 + 根目录图片） | 无 |

判定只看目录名：包内目录**包含**某标准 `FolderList` 的全部条目 → 归该标准（多出的目录不进抽图池，只在「检查完整性」里列为多余）；包内目录全部**落在**某标准清单内但有缺失 → 也归该标准，状态为可修复，可一键创建缺失目录。

### 标准三：三级规则块

按优先级选出规则块，再取块里球员种族码（0–10）对应的那条规则：

1. **国家块**：规则表里以该国籍三字码为键（如 `BRA`）；
2. **族群块**：以该国基础池目录名为键（如 `Mestizo`、`Afrocaribbean`）；
3. **全局默认块** `_DEFAULT_`：其余所有国籍。

每条规则有四种形态：

| 写法 | 含义 |
| :--- | :--- |
| `"default"` | 用归属者自己的目录（三级块下都等于该国的基础池 `Ethnics[国籍]`） |
| `{"typeOfMapping":"directly","directory":"Spain"}` | 直接映射到单一目录 |
| `{"typeOfMapping":"random","directory":["Japan","China"]}` | 等概率随机取一个 |
| `{"typeOfMapping":"randomWithWeight","directory":{"ethnicities":["Mestizo","NorthernSA"],"weights":[66,33]}}` | 按权重随机（权重按总和归一，不要求恰好 100） |

解析出的目录若在头像包里不存在或为空，按两级回退处理：**先退到该国基础池** `Ethnics[国籍]`，仍不可用再按 `Fallback` 字段处理（`random` = 从包内递归全池随机抽，默认值；`skip` = 跳过该球员不生成映射）。

### 编辑规则

界面里点「规则配置」进入结构化编辑工作台：左侧分区（概览 / 目录清单 / 国籍映射 / 种族码修正或规则块 / 全局设置），右侧按表格、目录标签、规则卡片逐项修改；「概览」会先做配置体检（重复目录、失效引用、缺 `_DEFAULT_` 等），点击问题可直接跳到对应分区。需要手改整份文件时，顶部切到「源码」即可编辑 JSON。也可用资源管理器打开 `data/rules/` 改 `standardN.json`（改完下次替换即生效）。保存与加载都会做结构校验：版本必须是 4、规则块键必须是国籍码或清单内目录名、每个块必须 0–10 全枚举、规则指向的目录必须在 `FolderList` 内、加权两列必须等长且全为正数。非法内容不会写盘，加载失败会报错并指明文件路径（不静默回退出厂默认，避免用改坏的规则抽图而不自知）。

`data/rules/template2.json` 这类旧命名文件会在启动时自动改名续用；已作废的旧标准三规则文件会被直接删除。

### 编辑国籍对照表

RTF 名单里的国籍（中文全称、英文全称或已经是三字码）先由**国籍对照表**归一化成三字码，再进入抽图与提示词。对照表在应用内点「国籍对照表」即可增删改，也可直接编辑 `data/nationalities.json`：

```json
{
  "languages": ["English", "简体中文"],
  "mappings": [
    { "code": "CHN", "language": "English", "name": "China" },
    { "code": "CHN", "language": "English", "name": "China PR" },
    { "code": "CHN", "language": "简体中文", "name": "中国" }
  ]
}
```

- 一行 = 一条映射；同一码在同一语言下可以有多条（全称与别名），解析时都算命中。中文规范名取该码下**最长**的中文全称（供 AI 提示词的 `nationality` 变量），如 `ALB` 的「阿尔巴尼亚」与截断别名「阿尔巴」都保留。
- 新增语言只需在 `languages` 里加一个节点，并给需要的码添加该语言全称；解析时按 `languages` 的顺序命中，因此德语、法语等导出也能自动识别。
- 保存前会校验：码必须是 2–3 位大写字母（`SC` 是两位特例）、语言必须在 `languages` 里、同一语言下同一全称不能指向两个码、至少保留一条映射。非法内容不会写盘。
- 应用内保存后**立即生效**（下一次扫描 RTF / 替换 / 提示词预览即用新表）；直接改文件则在下次扫描或替换前自动重读。出厂默认仍内嵌在 `assets/nat_translation.json` + `nat_codes.json`，删掉用户副本后重启会重新导出一份。

### 新增一个标准

判定层完全数据驱动，新增标准不用改判定代码，六步即可：`assets/standardN.json` → `src-tauri/src/templates/standardN.rs`（规则结构体 + 校验 + 抽图模型 + 单测，只依赖 `templates/mod.rs` 的接口）→ `assets.rs` 内嵌 → `templates/mod.rs` 登记（配置字段、加载导出、`folder_lists()`、`for_layout` 分支、`rule_files()`、已实现标准清单）→ 前端加一个 chip。命名一律跟着标准号走：`standardN.rs` ↔ `standardN.json` ↔ 类型 `StandardNConfig` / `StandardNRule`。

注意各标准的 `FolderList` 不能互相包含，否则判定会先命中先赢；加载时会校验这一点并报错。

### 目录名不在清单里的老头像包

若包里的目录（例如 `Scandinavian`）不在标准三的 62 目录清单内，判定结果是「无法识别」，替换时走递归全池随机：仍然能出图，但不按国籍与种族码路由。想恢复精确路由有两条路——在 `data/rules/standard3.json` 的 `FolderList` 里补上你包里的目录名，或点「一键创建缺失目录」把清单补齐。

## 故障排查

出问题时请先附上日志 `newgan.log` 再提 issue。最快的定位方式：点状态栏 `日志` 打开抽屉，把级别选到 `DEBUG` 复现一次，点 **打开日志文件** 直接打开日志（文件在数据目录：开发时为 `<项目根>\data\newgan.log`，安装后为 `<安装目录>\data\newgan.log`）。

| 现象 | 原因与处理 |
| :--- | :--- |
| `RTF 格式不合法：…` | 六种支持格式（基础/拓展球员/拓展职员 × 中英文）都不匹配，提示会定位到首个不合法字段与行号（旧版 14 列详细、性别第 3 列的旧职员拓展布局也已不再支持）。用本仓库 `views/` 最新视图重新导出 |
| `读取 RTF 失败` / `请先选择 RTF 名单` | 文件被移动、改名或未设置，重新在「当前任务」卡点 `选择RTF` |
| `标准N：缺少 N 个目录（已有 x/y）：…` | 头像包缺该标准要求的目录；点 `一键创建缺失目录`，或确认选的是头像包**根目录** |
| `无法识别头像包结构` | 子目录与任何标准的 `FolderList` 清单都不构成包含关系；替换时将递归全池随机。可在 `规则配置` 中把包内目录名补进清单恢复精确路由 |
| `标准三规则无效：…` / `标准规则文件无法解析：…` | `data/rules/standardN.json` 被改坏（版本不符、块缺码、目录不在 `FolderList` 内、加权两列不等长等）。错误信息会指明文件与具体键；也可删掉该文件让程序重新导出一份出厂默认 |
| 部分球员被跳过、没生成映射 | 该球员国籍码不在标准规则的 `Ethnics` 映射中（如 FM 用了非英文三字码），可在 `data/rules/standardN.json` 补该码，或提 issue 反馈 |
| RTF 中国籍查不到、整行被丢弃（警告日志提示「…不是国籍对照表收录的国籍全称，也不是对照表收录的国籍码」） | 名单里的国籍显示文本或截断别名未收录；点「国籍对照表」在应用内补一条映射（或直接改 `data/nationalities.json`），保存后下次扫描/替换即生效 |
| 名单里一个人都没换 | 勾了 `仅随机人`，但拓展名单第 10 列标志全为 `否/No`（名单里没有随机人）；关掉开关，或改用 `is newgen` 过滤视图重新导出 |
| 写 `config.xml` 失败 / 权限错误 | 以管理员（或 `sudo`）运行，或把头像包移到当前用户可写目录 |
| FM 里头像没变 | 未重新加载皮肤缓存；或 FM 图形缓存目录里存在旧的 `config.xml` 副本 |
| 替换秒过 / 日志显示「命中（复用，不扫盘）」 | 正常行为：头像包没变，索引缓存被复用，省下的是整包重扫。想强制重扫，在头像包的一级目录里增删任意一张图（签名随之变化）再执行替换即可 |
| 明明往头像包里加了图，替换却没用上 | 索引缓存仍在用旧的。签名只覆盖**一级目录**的 mtime 与直接子条目数，深层子目录里改名不会被察觉；在对应一级目录里增删任意图片即可让签名变化，或重启应用 |
| 符号链接 / 快捷方式指向的头像子目录没被识别 | 目录判定已兼容符号链接（macOS / Linux 软链、Windows junction 均可）；若仍不识别，确认链接目标可达且有读权限——目标不可达时按「读不到」处理，该子树不入池 |
