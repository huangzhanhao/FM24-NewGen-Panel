## 核查：禁重复与 Preserve 剔除是否对标准一/标准三同样生效（只读审查，未改代码）

结论：**是，两个机制都在框架层实现，与标准无关**，四个 PickRule 实现齐全。

- 唯一调用点 `face_mapper.rs:112-117`：`if !duplicates && mode == Mode::Preserve { rule.exclude_used(&used) }`；
  `duplicates` 来自前端全局勾选「允许复用图片」（ReplacePanel 默认 true → ReplaceParams.allow_duplicates
  → replace_flow.rs:218 → generate_mapping），没有任何按标准分支。
- 禁重复：标准一 `standard1.rs:29`（单根池 remove）；标准二 `standard2.rs:100`（选中池 remove）；
  标准三 `standard3.rs:392 drop_image`（**双索引 pools + recursive_pools 同步**，兜底路径
  `pick_from_pools_flat` 之后也要 `drop_image` 回摘主池）；Unknown `unknown.rs` → `pick_from_pools_flat`。
- 剔除键：标准一 = 裸词干（平铺 from 无目录前缀）；标准二/三/Unknown = `record_from(dir, stem)` 全路径。

发现的两处口径裂缝（未修，待用户决定）：
1. 标准三主池 `pools` 来自 `faces_map`（词干 = `legacy_face_stem`，取首个 '.' 前），兜底池
   `recursive_pools` 来自 `walk_recursive`（词干 = `image_stem` = `file_stem`）。含点号文件名
   （`a.1.png`）在两份索引里键不同（`a` vs `a.1`）→ `drop_image`/`exclude_used` 摘不掉另一份，
   理论上一张图可能在兜底阶段被二次发出（同一文件、两个不同 from）。标准一无此问题
   （root_images 统一用 image_stem），标准二只有一份索引。
   附带：`facepack_scanner.rs:119` 注释写「标准二 faces_map 专用」，但标准三的 pools 也吃 faces_map。
2. 端到端 Preserve + 禁重复（duplicates=false）**没有测试**：两个 preserve 测试（face_mapper
   `preserve_keeps_xml_and_skips_existing_uids` / `flat_preserve_keeps_existing_flat_entries`）
   都传 duplicates=true，`exclude_used` 在 e2e 里从未被真正触发；`exclude_used` 单测只有标准一
   （`standard1_picks_from_root_and_excludes_used`）与标准三（`exclude_used_removes_occupied_images`），
   **标准二自己没有**。

## 追加：词干口径修复的两条路线（回答用户追问后厘清）

`faces_map` 是 `PackScan` 的公共字段，生产点 `facepack_scanner.rs:194`（`legacy_face_stem`），
消费点 `templates/mod.rs:168`（标准二）与 `:170`（标准三）——两边共用同一份，所以：

- **路线 A（改生产者）**：动 `legacy_face_stem` → 标准二、标准三的池键与写出的 `from` 一起变
  （`a.1.png`：`Dir/a` → `Dir/a.1`；后者能被 `resolve_image_file` 命中，前者不能）。
  不波及标准一（`root_images` 本就用 `image_stem`，scanner 第 181 行），也不影响布局判定
  （`classify_scan` 只用目录名，`templates/mod.rs:214`）。
  **注意：这条漂移是静默的**——`scan_pack_standard2` 的注释写「e1 + e2（split 词干）」，
  但它用的文件名 e1.png/e2.jpg 在两种规则下词干相同，实际没有测试锁住 split 行为。
- **路线 B（改消费者，推荐）**：`Standard3Rule::new` 的主池不再从 `faces_map` 取，而是从
  `recursive_pools` 按 `FolderList` 名单过滤出来。`walk_recursive`（第 133-149 行）已按
  「每个目录一条、只放该目录直接图片、词干 = `image_stem`」建好，所以主池与兜底池**逐字同键**，
  `drop_image` 摘一份另一份必然同时生效，整类索引漂移消失；标准二零改动。
  （附带好处：FolderList 若写了多级目录名，今天匹配不到单级键的 `faces_map`，改后能匹配。）
