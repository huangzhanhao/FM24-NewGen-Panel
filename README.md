# NewGAN Manager

> 为 Football Manager 的 NewGAN / 随机人批量匹配头像（facepack）的桌面工具。
> 随机人名单可来自 FM24 导出的 RTF、FM24 `.fm` 存档，或 Windows 上正在运行的 FM24 游戏进程。

![Tauri Build](https://github.com/huangzhanhao/FM24-NewGen-Panel/actions/workflows/tauri.yml/badge.svg)

**当前版本：v2.0.0** ｜ Fork 自 [Maradonna90/NewGAN-Manager](https://github.com/Maradonna90/NewGAN-Manager) ｜ 基于 **Tauri 2 + Rust + Svelte 5 + TypeScript** 重构，无需 Python / .NET 运行时。

## 功能概览

- **三种名单来源**：扫描 RTF、直接解析 FM24 `.fm` 存档、只读扫描运行中的 FM24 进程；三种来源统一生成球员 / 职员名单缓存。
- **Profile 与头像包组**：按游戏存档建立 Profile，每个 Profile 可关联多个头像包目录；下拉选择用于浏览，点击 **激活** 才切换当前存档，并按组保存、恢复 `config.xml` 快照。
- **三种替换模式**：保留（Preserve）、覆写（Overwrite）、生成（Generate），支持仅随机人、禁止重复使用图片和写入前备份。
- **多种头像包标准**：支持直铺随机、标准二 14 目录、标准三 126 目录，以及无法识别结构的递归全池随机。
- **大名单渐进加载**：后端按每块 8192 条推送名单，首批到达即可浏览；搜索、筛选、排序和分页在前端已加载的数据上执行。
- **批量与单人替换**：批量生成映射后，仍可按 UID、姓名、国籍或俱乐部查找人员，单独指定图片、重掷或送往 AI 生图。
- **AI 生成头像**：内置多家在线服务商与本地 ComfyUI，支持提示词编辑、结果画廊和多人队列。
- **规则可视化编辑**：在应用内维护标准规则、目录清单、国籍映射和国籍对照表；加载与保存均进行规则校验。
- **便携数据与安全回退**：用户数据集中在程序旁的 `data/`，写入前可自动备份，提供应用内日志、进度显示和取消操作。

## 安装与准备

### Windows 安装

1. 从 [Releases](https://github.com/huangzhanhao/FM24-NewGen-Panel/releases) 下载 Windows NSIS 安装包，例如 `NewGAN-Manager_2.0.0_x64-setup.exe`。
2. 安装到当前用户目录，通常无需管理员权限；运行游戏内存读取时，如果进程打开失败，可尝试以管理员身份运行本工具。
3. 应用使用系统 WebView2。Windows 10/11 通常已内置，缺失时按安装引导补齐。
4. 当前安装包未购买代码签名证书。如遇 SmartScreen 或杀毒软件提示，请先确认安装包来源。

当前仓库的正式安装包配置仅包含 **Windows NSIS（currentUser）**。CI 会执行 Windows、macOS、Linux 构建矩阵，但这不等同于为三个平台都提供相同形式的安装包；其他平台可从源码构建。**运行中游戏内存读取仅支持 Windows。**

### 准备头像包

准备一个包含头像图片的目录，并在 Profile 下将它关联为“头像包（组）”。程序会根据目录结构识别所用标准。

- 标准二使用 `African`、`Asian`、`Caucasian`、`Central European`、`EECA`、`Italmed`、`MENA`、`MESA`、`SAMed`、`Scandinavian`、`Seasian`、`South American`、`SpanMed`、`YugoGreek` 共 14 个目录。
- 标准三使用更细分的 126 个目录，完整清单以 `standard3.json` 的 `FolderList` 为准。
- 图片支持 `png`、`jpg`、`jpeg`；本仓库只提供映射工具，不附带头像图片。
- 可在“存档资料”工作台执行 **检查完整性**，按规则识别标准、查看缺失目录，并一键创建缺失目录。

### 仅在 RTF 路线需要：安装 FM 视图与过滤器

将仓库中的 `views/` 和 `filters/` 复制到 FM 用户目录：

- Windows：`文档\Sports Interactive\Football Manager 20XX\`
- macOS：`~/Library/Application Support/Sports Interactive/Football Manager 20XX/`

在 FM 中使用 `SCRIPT FACES` 或仓库提供的 Newgen 视图，配合 `is newgen search filter` 筛选随机人，再将列表导出为 RTF。

## 快速使用流程

1. **新建并激活 Profile**：启动后默认处于 `No Profile`，不会自动恢复上次激活的存档。新建 Profile 后会立即激活；仅在列表中选中其他 Profile 属于浏览，不会切换写入目标。
2. **关联头像包并选择组**：一个 Profile 可关联多个头像包目录，每组分别保存 RTF、`.fm` 路径和映射快照。
3. **生成名单缓存**：在“存档资料”工作台任选一种方式——扫描 RTF、扫描 FM24 `.fm` 存档，或读取运行中的 FM24。
4. **检查头像与名单**：按需执行完整性检查、扫描头像，并在名单预览中核对人员、国籍和随机人标记。
5. **执行替换**：进入“批量/单人头像替换”，选择模式与选项后启动。需要时再用单人替换微调。
6. **回到 FM 生效**：在“偏好设置 → 界面”中重新加载皮肤，必要时清理图形缓存并重启 FM。

> **批量替换不会自动扫描名单。** 它只消费最近一次成功扫描得到的缓存。缓存为空时会直接失败，不会补扫 RTF、`.fm` 或游戏内存，也不会写入 `config.xml`。批量替换的就绪条件是：已激活 Profile、已选择组、名单缓存非空。

## 名单来源与统一缓存

| 来源 | 支持范围 | 适用场景 |
| :--- | :--- | :--- |
| RTF | 基础名单、拓展球员、拓展职员；中文或英文数据 | 各版本 FM 的通用路线，也是非 FM24 存档的推荐路线 |
| `.fm` 存档 | **仅 FM24** | 不想从游戏导出 RTF，直接读取存档中的球员与职员 |
| 运行中游戏 | **仅 Windows + 已验证的 FM24 构建** | 游戏已运行并载入存档时，直接读取当前数据库 |

### RTF 格式

扫描器以表头和数据行共同识别格式，支持 **3 类结构 × 2 种数据语言**：

| 格式 | 列数 | 说明 |
| :--- | :--- | :--- |
| 基础名单 | 7 | UID、国籍、第二国籍、姓名、发长、发色、种族码；名单内人员全部按随机人处理 |
| 拓展球员 | ≥18 | 在基础字段上增加肤色、Newgen、性别、年龄、身高、俱乐部、所在地、CA、PA、R.C.A 等字段，可带额外自定义列 |
| 拓展职员 | ≥18 | 与拓展球员结构相近，第 15 列为“偏好工作”而不是“所在地” |

国籍显示文本会先通过国籍对照表归一化为三字码。无法识别或不合法的数据行会被跳过并记录警告；整份文件不符合支持格式时会给出具体错误。旧版 14 列详细名单及旧职员拓展布局不再支持。

基础名单的 UID 会统一加上 `r-` 前缀；拓展名单根据第 10 列 `Newgen` 的 `是/否` 或 `Yes/No` 决定是否添加该前缀。替换选项“仅随机人”即按此前缀过滤。

### FM24 `.fm` 存档

- 直接解析存档中的球员与职员，生成混合名单，不需要先导出 RTF。
- 仅放行 FM24 数据布局，其他 FM 版本会在解析前明确拒绝；请改用 RTF。
- 存档无法提供的字段会留空，不会猜填。中文姓名不能从存档还原，姓名主要提供拉丁转写；R.C.A、所在地、偏好工作等字段也可能为空。
- 选择并扫描 `.fm` 前，需要先激活 Profile 并选择头像包组。

### 运行中的 FM24

- 只读进程内存，**不会写入游戏或存档**。
- 仅支持 Windows，要求 FM24 已启动并载入存档。
- 当前验证的构建为：Steam 24.4.0、Steam 24.4.1 Beta、Steam 24.4.2、Epic 24.4.2。
- 工具会核对可执行文件 SHA256。未识别的构建会显示哈希并拒绝读取，不会按未知偏移猜读。
- 如果确认游戏已运行但仍无法打开进程，可尝试以管理员身份运行本工具。

### 缓存与名单预览

- 三种扫描成功后会覆盖同一份名单缓存，并记录来源；扫描失败不会用空结果覆盖旧缓存或旧预览。
- 名单缓存仅存在于本次应用运行期间。切档、切组或更改当前 RTF 会清空相关缓存，之后需要重新扫描。
- 后端按 **8192 条 / 块**流式推送，前端渐进渲染并加载名单，不是只向后端请求当前页。超大名单仍会占用相应的前后端内存。
- 搜索、随机人筛选、球员 / 职员筛选、排序和分页均在前端已加载数据上执行；随机人筛选默认为“任意”，混合名单可切换人员类别。
- 预览表的搜索、筛选、排序和勾选不会改写名单缓存，也不会改变批量替换的输入范围；批量替换是否只看随机人由执行面板中的“仅随机人”选项单独决定。

## 工作台与替换操作

| 工作台 | 主要用途 |
| :--- | :--- |
| **存档资料** | 管理名单来源、检查头像包、扫描头像、读取组级 `config.xml` 快照、编辑标准规则和国籍对照表，并预览名单 / 快照 |
| **批量/单人头像替换** | 左栏执行批量替换和单人微调，右栏查看共享的名单 / 快照预览 |
| **AI 生成头像** | 配置服务商与模型、编辑提示词和参数、生成图片、管理画廊与批量队列 |

顶栏状态点只有两种颜色：**绿色**表示当前工作台核心条件已就绪，**橙色**表示仍缺少前置条件。状态点只作提示，不会阻止切换工作台；具体缺项进入相应工作台查看。

### 批量替换模式

| 模式 | 行为 |
| :--- | :--- |
| **保留 Preserve** | 保留现有映射，只为尚未分配头像的人员补图 |
| **覆写 Overwrite** | 重新抽取名单范围内的人员，名单之外的已有映射继续保留 |
| **生成 Generate** | 忽略现有 `config.xml`，按本次名单从零生成；既有映射非空时会在执行前提示确认 |

常用选项：

- **允许复用图片**：关闭后尽量避免不同人员重复使用图片；保留模式下会先剔除已被现有映射占用的图片。
- **仅随机人**：仅处理 UID 带 `r-` 前缀的人员。
- **写入前备份**：写入 `config.xml` 和档景快照前创建滚动备份。

执行前还会进行完整性兜底检查。头像包缺目录或结构无法识别时，可根据提示决定是否继续；Generate 模式另有空映射预检，避免未确认就清空现有配置。替换过程中可取消，完成后会同步当前组的映射快照。

### 单人替换

在替换工作台左栏可按 UID、姓名、国籍或俱乐部搜索人员，并执行：

- **指定替换**：选择头像包内的 `png`、`jpg` 或 `jpeg` 图片，只修改当前人员的映射。
- **重掷替换**：按当前头像包标准与规则重新抽图。
- **送生图**：将当前人员送到 AI 工作台，作为提示词与生成任务的来源。

## 头像包标准与抽图规则

程序根据头像包目录与各标准 `FolderList` 的关系识别标准。一个标准由目录约定、规则 JSON 和抽图模型共同组成。

| 标准 | 包结构 | 当前抽图行为 |
| :--- | :--- | :--- |
| **标准一** | 图片直接放在根目录 | 从根目录图池随机，不按国籍或种族路由 |
| **标准二** | 14 个种族 / 大区目录 | 只处理球员；按国籍映射、种族码修正选择目录，职员显式跳过 |
| **标准三** | 126 个细分目录 | 按男球员、女球员、男职员、女职员四类人员分别路由 |
| **无法识别** | 不符合任何已登记标准 | 递归扫描整个头像包并全池随机，不按国籍或人员类别路由 |

### 标准二

标准二根据 `Ethnics` 国籍映射和种族码修正选择目标目录。**目标目录不可用或抽池耗尽时，会在 `FolderList` 范围内的其他可用目录中回退，而不是直接跳过球员。** 职员不参与标准二替换，会记录为不适用并跳过。

设计细节见 [抽图模型设计-标准二](docs/抽图模型设计-标准二.md)。

### 标准三

标准三的 126 个 `FolderList` 目录分为：

- 62 个男球员目录；
- 32 个女球员目录；
- 18 个男职员目录；
- 14 个女职员目录。

男球员依次解析 **国家块 → 族群块 → `_DEFAULT_`**，再按种族码取得具体规则；女球员和男女职员使用各自的人员类别与目录映射。规则支持默认目录、直接映射、随机列表和加权随机。

规则目录及基础池均不可用时，由 `Fallback` 决定后续行为：

- `random`：在**同一人员类别**的 `FolderList` 目录中兜底，不是递归整个头像包；
- `skip`：跳过该人员，不生成映射。

禁重复抽取按目录维护发牌池，发完后重新洗牌；Preserve 且禁重复时，会先剔除已占用图片。

完整规则见 [抽图模型设计-标准三-兼容NG-regens头像包](docs/抽图模型设计-标准三-兼容NG-regens头像包.md)。FM 种族码示例可查看 [FM NewGAN种族代码示例](docs/FM%20NewGAN种族代码示例.html)。

### 编辑标准规则

“规则配置”提供结构化编辑和 JSON 源码编辑。用户副本位于：

- `data/rules/standard2.json`
- `data/rules/standard3.json`

标准二和标准三在加载与保存时都会执行结构及语义校验，包括目录引用、规则块、权重和必要字段等。非法配置会报错，不会静默回退出厂默认。不同标准的 `FolderList` 必须**交集为 0**，否则标准归属会产生歧义。

### 编辑国籍对照表

“国籍对照表”用于维护国籍三字码与各语言全称、别名之间的关系，用户副本为 `data/nationalities.json`。RTF 国籍归一化、抽图规则和 AI 提示词都会使用这份数据。删除用户副本后，应用会在后续启动时重新导出出厂默认。

## AI 生成头像

AI 工作台为可选功能，支持：

- OpenAI；
- SenseNova；
- 阿里云百炼；
- 火山方舟；
- 硅基流动；
- 魔搭 ModelScope；
- 本地 ComfyUI（无需在线 API Key）。

可编辑提示词、按模型能力调整参数、保存生成结果，并从名单勾选多人加入队列。队列支持手动确认、自动执行和运行中取消，产物保存到对应头像包组的 `_generated/` 目录。

- 在线服务商 Key 以**机器绑定密文**保存在 `data/image_ai.json`，明文 Key 只在本机内存中短暂使用。
- 生成队列是本次会话的内存状态，不跨应用重启保留。
- 队列条目绑定入队时的 Profile 与组；队列运行中切换作用域会先提示，并在确认后取消未完成任务。

## 数据目录、快照与备份

开发模式的数据写入 `<项目根>/data/`；正式运行写入 `<可执行文件所在目录>/data/`。WebView 数据也重定向到该目录，不集中写入系统 AppData。

```text
data/
├─ .user/                  # Profile、组配置与各组映射快照
├─ rules/                  # standard2.json、standard3.json 用户副本
├─ prompts/                # AI 提示词模板用户副本
├─ nationalities.json      # 国籍对照表用户副本
├─ image_ai.json           # AI 配置与机器绑定的 Key 密文
├─ .imgtmp/                # AI 临时图片与画廊记录；记录可跨会话保留
├─ webview/                # WebView 缓存与本地存储
└─ newgan.log              # 运行日志
```

- Profile 下拉选择只用于浏览；激活时会保存旧档各组快照，并恢复目标档快照到相应头像包目录。
- 开启写入前备份时，`config.xml` 会生成带时间戳的备份，每个头像包目录保留最近 5 份；档景快照覆盖前也按同样策略保留最近 5 份。
- 日志单个文件达到 10 MB 后滚动，保留最近 3 份滚动备份。状态栏的“日志”抽屉支持级别筛选、错误角标和打开日志文件；扫描或替换完成后的进度会保留约 20 秒。

## 开发与测试

### 环境要求

- Node.js 20+；
- pnpm 9+；
- Rust 工具链；Windows 建议使用 MSVC target；
- 运行桌面应用所需的平台 WebView 依赖。

### 常用命令

```bash
# 安装前端依赖
pnpm install

# 启动桌面开发模式（前端热重载 + Rust 后端）
pnpm tauri dev

# 仅启动 Vite 前端 / 构建前端
pnpm dev
pnpm build

# Rust 测试
cargo test --manifest-path src-tauri/Cargo.toml

# 前端测试与 Svelte / TypeScript 检查
pnpm test
pnpm check

# 构建桌面包，产物位于 target/release/bundle/
pnpm tauri build
```

开发服务器固定使用 `1420` 端口。`pnpm tauri dev` 会先通过 `scripts/dev-server.mjs` 检查该端口上是否已经是本项目的 Vite 页面，是则复用，否则再启动开发服务器。Rust 构建产物统一位于项目根目录的 `target/`。

CI 工作流位于 `.github/workflows/tauri.yml`，包含 Rust 测试、前端测试以及 Windows / macOS / Linux 构建矩阵。

### 项目结构

```text
├─ src-svelte/                 # Svelte 5 前端
│  └─ lib/
│     ├─ components/           # 布局、存档资料、替换、结果、AI 等组件
│     ├─ stores/               # 应用、界面、日志与 AI 队列状态
│     └─ api.ts / types.ts     # Tauri IPC 封装与类型
├─ src-tauri/                  # Tauri 2 / Rust 后端
│  ├─ assets/                  # 内嵌的国籍、规则与 AI 默认配置
│  └─ src/
│     ├─ commands.rs           # 前端命令入口、缓存与任务进度
│     ├─ rtf_scanner.rs        # RTF 识别与名单解析
```

## 故障排查

优先打开状态栏的 **日志** 抽屉复现问题，并附上 `data/newgan.log`。

| 现象 | 处理方式 |
| :--- | :--- |
| 提示名单缓存为空 | 先在“存档资料”中成功完成一次 RTF、`.fm` 或运行中游戏扫描；批量替换不会自动补扫 |
| 扫描后仍看到旧名单 | 扫描失败会保留旧缓存和旧预览；查看错误弹窗与日志，确认本次扫描是否成功 |
| `.fm` 被判定为不支持 | 直接存档解析仅支持 FM24；其他版本请从游戏导出 RTF |
| 运行中游戏读取失败 | 确认 Windows、FM24 已运行并载入存档、构建在支持列表内；必要时尝试管理员身份运行。未识别构建请附日志中的 SHA256 反馈 |
| `RTF 格式不合法` | 使用仓库最新 `views/` 重新导出，核对是基础、拓展球员还是拓展职员格式，并检查提示中的行号和字段 |
| 头像包缺少目录 | 确认选择的是头像包根目录，再执行“检查完整性”和“一键创建缺失目录” |
| 无法识别头像包结构 | 可继续按递归全池随机替换，或在规则配置中修正目录清单以恢复精确路由 |
| 标准二中部分人员始终被跳过 | 标准二当前只处理球员，职员会显式跳过；需要按人员类别路由时使用兼容的标准三头像包 |
| 勾选“仅随机人”后无人可换 | 检查名单中是否确有 `r-` UID；RTF 拓展名单需正确填写 Newgen 标志，预览筛选不会替代执行面板选项 |
| 深层目录新增图片后未参与抽图 | 执行一次“扫描头像”强制重建索引。自动缓存签名主要观察一级目录，深层变更不一定触发自动重扫 |
| 写入 `config.xml` 失败 | 检查头像包目录是否可写、文件是否被其他程序占用，并将头像包移到当前用户有权限的位置 |
| FM 中头像没有变化 | 重新加载皮肤，必要时清理 FM 图形缓存并重启；同时确认写入的是当前使用的头像包目录 |

## 从 v1 升级

v2 首次启动会尝试从旧版便携数据目录或 `%LOCALAPPDATA%\NewGAN Manager\.user` 迁移用户数据到当前的 `data/.user/`：

- 仅在目标位置尚无完整数据时迁移，不覆盖已有新配置；
- 迁移采用复制，旧版原件保留，失败只记录警告，不阻止应用启动；
- Profile、组设置和映射快照会随数据目录一并保留。
