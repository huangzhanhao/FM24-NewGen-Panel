# NewGAN Manager 标准二抽图模型说明

> 适用头像包：按 **14 个种族/大区分目录**组织的头像包（African、Asian、Caucasian、Central European、
> EECA、Italmed、MENA、MESA、SAMed、Scandinavian、Seasian、South American、SpanMed、YugoGreek）。
> 规则真源：`src-tauri/assets/standard2.json`（出厂内置）与 `data/rules/standard2.json`（用户可编辑副本）；
> 实现：`src-tauri/src/templates/standard2.rs`。
> 与[标准三（NG Regens）反推文档](ng-regens-抽图模型反推.md)并列：标准三是对外部配置的反推，
> 标准二则是对本项目 v1（Python 版）行为的数据化继承，见 §7。

## 1. 配置结构（schema 与命名语义）

| 键 | 含义 |
|---|---|
| `FolderList` | 抽图池白名单（14 个一级种族/大区目录）。清单外的多余目录与空目录都不进抽图池。 |
| `Ethnics` | 国籍三字码 → 基础种族目录（240 国，值域恰好覆盖全部 14 个目录）。同时是未配置种族码时的兜底归属。 |
| `CodeRules` | FM 种族码 `"0"`–`"10"` 的修正规则：`{"prefer":[目录…], "fallback":目录}`。prefer 按序匹配主/第二国籍的种族目录，都不命中用 fallback。 |

`CodeRules` 单条语义（`apply_code_rule`）：

- `prefer` 列表中取**第一个**「等于主国籍种族目录 e1 或第二国籍种族目录 e2」的目录；
- 一个都不命中 → 取 `fallback`；
- `prefer` 与 `fallback` 同值即「固定码」（码 4/5/7/8，与国籍无关，恒落指定目录）；
- 该码在 `CodeRules` 中缺失 → 沿用主国籍目录 e1（内置表 0–10 齐全，仅用户改坏 json 时才会走到）。

内置 11 条规则全表：

| 码 | prefer（按序，命中 e1/e2 即用） | fallback | 备注 |
|---|---|---|---|
| 0 | Scandinavian, Caucasian | Central European | 北欧/白人 |
| 1 | Caucasian, EECA, Italmed, SAMed, SpanMed, YugoGreek, South American | Central European | 地中海/西语裔 |
| 2 | MESA | MENA | 中东/北非 |
| 3 | South American | African | 非洲/加勒比 |
| 4 | MESA | MESA | 南亚，固定 |
| 5 | Seasian | Seasian | 东南亚，固定 |
| 6 | SAMed | African | 太平洋岛民 |
| 7 | South American | South American | 美洲原住民，固定 |
| 8 | Seasian | Seasian | 澳洲原住民，固定 |
| 9 | South American | African | 黑白混血 |
| 10 | MESA, Seasian, South American | Asian | 东亚 |

## 2. 种族代码 0–10 语义

代码即 FM 存档 / RTF 名单中球员自己的「种族」字段（与标准三同一张码表）：

| 代码 | 含义 | 代码 | 含义 |
|---|---|---|---|
| 0 | 北欧/白人 | 6 | 太平洋岛民 |
| 1 | 地中海/西语裔 | 7 | 美洲原住民 |
| 2 | 中东/北非 | 8 | 澳洲原住民 |
| 3 | 非洲/加勒比 | 9 | 黑白混血 |
| 4 | 南亚 | 10 | 东亚 |
| 5 | 东南亚 | | |

与标准三不同：标准二不使用 `DefaultCodes`——码直接来自名单解析，不需要按国籍先抽一个码。

## 3. 抽图解析流程（端到端）

```
输入: 主国籍 N1、第二国籍 N2（可空）、种族码 c（均取自 RTF 名单该行球员字段）

1) 国籍查表（json Ethnics）:
   e1 = Ethnics[N1]；查不到 → 该球员跳过（pick 返回 None）
   e2 = N2 非空时 Ethnics[N2]，否则 None（查不到同 None）
2) 种族码修正（json CodeRules）:
   ethnicity = apply_code_rule(c, e1, e2)
3) 池校验:
   抽图池 = 头像包一级子目录中「名字在 FolderList 内且非空」者
   ethnicity 不在池内（包内缺该目录或为空）→ 该球员跳过
4) 池优先级 image_pool_dirs（v1 继承语义）:
   ① 国籍同名目录：池里存在名为 N1 的目录 → 先用
   ② ethnicity 目录
   ③ ①②都不在池 → 使用全部池目录
5) 依序取第一个非空池，池内等概率随机抽一张；
   禁重复（allowDuplicates=false）时把抽中的图从内存池中摘除
输出: PickedImage { dir: ethnicity, stem } → config.xml 的 from = "ethnicity/stem"
```

**内置数据下的实际收敛**：池键是 14 个大区英文名，而 N1 是三字国籍码（如 `ESP`），①永不命中；
③在第 3 步守卫之后也不可达（ethnicity 已在池内）。因此出厂配置下池恒为 `[ethnicity]`：
**修正到哪个大区目录，就只在该目录里等概率抽图**。①与③是从 v1 继承的扩展位——
用户若自定义 `FolderList` 加入国籍同名目录，①才会生效（此时 from 的目录名仍取修正后的 ethnicity，
图片词干可能来自国籍目录，为 v1 既有行为）。

## 4. 禁重复与 Preserve 剔除

- **允许复用图片**：每名球员独立等概率抽取，可重复。
- **禁重复**：抽中即从该球员所属目录的内存池中摘除，抽完该目录即空，后续落到该目录的球员跳过。
- **Preserve 模式**（保留已换过的球员）：抽图前把 config.xml 已引用的图按
  `"目录/词干"` **全路径精确匹配**从各池剔除——只剔除本目录里被占用的同名图，不跨目录误伤同名文件。
- **词干口径唯一**：图片名一律取 `file_stem`（`"a.1.png"` → `"a.1"`，`facepack_scanner::image_stem`），
  扫描池、`from` 写入、config.xml 解析/回填三处同规则——同一张图在全链路只有 `"目录/a.1"` 一个身份，
  上面两条的匹配（以及标准三主池与兜底池的同步摘除）才成立。

## 5. 头像包判定（标准归属）

判定与抽图分离，唯一真源在 `facepack_scanner::classify`，按各标准登记的 `FolderList` 两轮推断
（标准按号升序，先命中先赢）：

1. **超集轮**：包内一级目录包含某标准清单的全部目录 → 判为该标准且「完整」（允许包内多出清单外目录，
   抽图时由 FolderList 排除）；
2. **子集轮**：包内目录全部落在某标准清单内 → 判为该标准但「不完整」（前端可一键创建缺失目录）；
3. 都不命中 → 无法识别（递归全池随机）。

标准二清单（14）与标准三清单（62）**交集为 0**，不存在互相包含，两轮先命中先赢不会错判；
`validate_registry` 把「任意两份清单不得互相包含」作为硬约束守卫，用户改规则后加载即校验。

## 6. 规则文件与可编辑性

- **内置默认**：`src-tauri/assets/standard2.json` 编译期内嵌（`STANDARD2_RAW`），启动时反序列化，
  格式错误直接 panic（出厂资产不应损坏）。
- **用户副本**：首次运行导出到 `<数据目录>/rules/standard2.json`；已存在则**永不覆盖**。
- **加载优先级**：用户文件存在且合法 → 用之；缺失 → 内置默认；JSON 损坏 → 报错（错误信息含文件路径），
  不静默回退。
- **保存**：规则编辑器保存时先解析再原子写回（pretty 格式化，顺带规范化手改格式）；非法 JSON 拒绝写盘。
- **校验强度（与标准三的刻意差异）**：标准二保存只做 JSON 解析，**没有**标准三那样的语义 `validate()`
  （serde 对缺失字段取默认值：空清单/空码表都能加载）。删改 `Ethnics`/`CodeRules` 条目即按
  「查不到国籍 → 跳过」「缺该码规则 → 沿用主国籍目录」的兜底语义生效，改坏的影响面仅限对应条目。

## 7. 来源与确认状态

- **逻辑来源**：v1 Python 版 `FaceMapper.correct_ethnic`（码 0–10 的修正分支）与
  `_get_image_pool`（国籍同名目录 > 种族目录 > 全部目录的池优先级），原文记录见
  [legacy-python/ARCHITECTURE.md](legacy-python/ARCHITECTURE.md)。
- **数据化**：Rust 版不硬编码任何目录名与码表，v1 的 `correct_ethnic` 逐分支被整理成
  `CodeRules` 数据表；测试 `apply_code_rule_matches_legacy_correct_ethnic` 对 0–10 全分支
  （含第二国籍命中、固定码、未配置码）断言与旧行为逐分支等价。
- **已确认的内置数据**（单测锁定）：
  - `FolderList` 14 项；`Ethnics` 240 国，14 个目录全部被引用，无死目录；
  - `CodeRules` 0–10 共 11 条齐全；
  - 国籍分布：African 103、South American 19、EECA 19、MESA 17、Caucasian 14、
    Central European 12、MENA 10、Asian 10、Seasian 10、YugoGreek 9、Scandinavian 7、
    SpanMed 4、Italmed 4、SAMed 2（合计 240）；
  - 抽查锚点：AFG→MESA、ARG→SAMed、ESP→SpanMed。

## 8. 与标准三的差异对照

| 维度 | 标准二 | 标准三 |
|---|---|---|
| 图像池 | 14 个种族/大区目录 | 62 个（国籍级 + 4 族群 + 纯目的地） |
| 国籍表 | `Ethnics` 240 国 → 14 目录 | `Ethnics` 233 国 → 62 池 |
| 决策依据 | 国籍查表 + 种族码修正（prefer/fallback） | 三级规则块：国家块 → 族群块 → `_DEFAULT_` |
| 规则形态 | 仅「有序候选 + 兜底」 | directly / random（等概率）/ randomWithWeight（整数权重）/ `"default"` |
| 缺目录时 | **跳过该球员**（不抽图） | 两级回退链：本国基础池 → `Fallback`（random/skip） |
| 规则文件校验 | JSON 解析 + 原子写（无语义校验） | `validate()` 硬约束：Version=4、块键合法、每块 0–10 全枚举、目录在清单内、权重等长为正 |
| 模型来源 | v1 行为继承（有等价测试） | 对 NG Regens Manager 25 `base_config.json` v4 的反推 |
| 分发入口 | `for_layout` 命中 `Standard{standard:2}` | 命中 `Standard{standard:3}` |
